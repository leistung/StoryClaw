# framework-design

## Description

设计或重构小说总纲、分卷和连载阶段，把作者的题材承诺转化为有因果、代价与阶段变化的故事结构；不用于直接写正文。

## Parameters

读取作者想写的读者体验、题材、主角起点、核心关系、已确认设定、已有正文与写作模式。确认目标是方案讨论、计划预览、正式展开还是重构后续；字数、卷数和范围以作者已确认计划为准。

## Method

1. 先区分既成事实、作者硬约束、可调整方向和待确认假设。已有正文决定故事已经走到哪里，旧大纲只说明过去打算怎样走；不能为适配新纲抹去正文结果。
2. 写出故事发动机：主角持续追求什么，什么人或制度在阻挡，双方凭什么行动，冲突为何会随选择升级。把“商战”“成长”等题材标签具体化为资源、交易、利益与代价。
3. 确定读者承诺及其兑现方式：悬疑需要可回看证据，感情需要关系中的决定，成长需要能力边界与付出。副线与主题通过事件发生联系，避免另写一份主题宣言。
4. 按局面变化划分卷或阶段。每卷写明起始局面、阶段目标、关键对手、连续事件、重要选择、关系变化、阶段结果与遗留问题；相邻卷通过上一卷的后果衔接，不能只是换地图重演。
5. 把主角、关键配角和对手放在同一因果链中。给对手能成立的目标和策略，说明配角的自主行动怎样改变主线，而不是仅列姓名与功能。
6. 规划信息与悬念：区分作者知道、读者已知和角色已知；列清线索准备、误导来源、揭露条件及阶段回收方向。远期回收是候选，不得标成已发生。
7. 连载模式详写当前及近期阶段，远期保留分歧条件与可调整终点；定长模式按已确认范围检查铺垫和收束是否放得下。卷数由故事与计划决定，不套固定章数公式。
8. 对每卷做因果压测：删掉其中关键选择后，后续是否仍照样发生？若是，补充真正改变局面的行动与代价。检查升级是否只是重复加码、是否靠对手失智或临时加规则解围。

## Constraints

- 方案尚未确认时提供候选方向、展开范围、主要缺口；已有生成计划时直接按计划展开，不在每卷重复要求作者确认。
- 不凭空承诺精确字数、Token、积分或爆款效果；规模可给依据和假设，费用使用系统估算。
- 不用“经历磨难、关系升温、迎来高潮”替代具体事件；也不为凑细节预写作者没要求的整本章纲。
- 现实题材的行业、历史、地域信息不足时标待查；暂定背景不能写成考据结论。
- 此 Skill 提供创作方法；保存、采用、计费、发布和数据访问权限由调用能力决定。输出服从调用方 schema，不把方法示例变成新接口。

## Output

讨论阶段给可比较方案与少量影响方向的关键问题；展开阶段交付调用方要求的 overview、volumes 等字段，细节放在对应文本字段。每卷能看出“谁因为什么做了什么，局面因此怎样改变”。重构时说明保留事实与未来变化，实际输出格式以调用方为准。
