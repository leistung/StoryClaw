# naming

## Description

为书籍、卷、章、人物、地点或组织生成贴合内容、时代与声音的命名候选，说明差异并检查现有范围内的混淆和剧透。

## Parameters

读取命名对象、题材、故事核心、使用场景、作者偏好的长度与风格、已存在名称及允许透露的信息。未给对象时根据当前任务判断，关键歧义再询问。

## Method

1. 抓命名真正要承载的信息：人物身份、地方特征、组织立场、章节事件或书籍承诺。名称应与实际内容有关，不仅追求气势、冷僻字和华丽意象。
2. 按对象选择策略。书名传达作品体验与辨识点；卷名呈现阶段变化；章名贴近本章而不过早揭露真相；人物与地名优先可读、可辨和语境适配。
3. 形成有差异的候选组，可从具体物象、行动冲突、人物关系、身份或主题切入。不要把同一短语调整标点、换近义字后当成多个方向。
4. 与输入的名称表比较：同音近形、共享后缀、过于相似的简称、同一人物别名与其他人物姓名冲突。别名沿用既有映射；命名建议不能自行合并实体。
5. 按题材与时代检查语感。现实背景不随意使用不合语境的头衔或术语；幻想名称也应能让人物自然称呼。不确定的历史词义或文化含义标待核实。
6. 检查剧透与误导。悬疑章名不提前点凶手，书名不承诺正文根本没有的设定、关系或结局；作者明确允许直白剧透时可按其选择。
7. 给出简短、具体的理由与取舍，例如易记但较直白、贴近核心物件但偏含蓄。推荐依据当前文本，不能把个人审美说成平台规则。
8. 作者反馈后沿选中方向微调，保留已确认禁用字、长度和风格；不默认重命名全书或自动替换已有正文。

## Constraints

- 无实际检索不能承诺全网唯一、未注册、可商用或保证点击率；已有范围查重与全网核查分开。
- 不假装候选已被作者采用，不生成修改数据库的指令。
- 数量服从请求，不用大量近似标题凑数；说明保持简洁，不掩盖候选本身。
- 不为显得高级堆冷僻字、难读音或无关典故；明确要求此风格时仍说明可读性取舍。
- 此 Skill 提供创作方法；保存、采用、计费、发布和数据访问权限由调用能力决定。输出服从调用方 schema，不把方法示例变成新接口。

## Output

输出命名候选及调用方允许的简短理由或分组。只有正文字符串接口时使用清楚的候选列表；严格 JSON 时使用其既有字段，不额外附查重证明或采用声明。
