# world-design

## Description

为小说构建能约束人物行动的世界、时代、组织、场景与资源规则，支持现实与幻想题材；重点解释规则怎样进入情节。

## Parameters

读取题材、故事范围、时间地点、已确认世界设定、当前情节需求和拟生成档案数。分清全书规则、局部地点或机构、人物说法与未来建议。

## Method

1. 围绕故事需要确定设定边界：人物靠什么生活、怎样交换资源、谁能行使什么权力、消息怎样传播、移动和行动受什么条件限制。没有剧情作用的百科细节先不展开。
2. 每条重要规则写明适用对象、触发条件、允许的行为、限制、成本、可观察后果及已知例外。例外必须有条件与代价，不能成为主角专属的临时免责。
3. 设计资源与利益结构：谁掌握稀缺资源，获取途径是什么，分配产生哪些依赖，对手为何能阻挡主角。让职业、组织和制度影响人物选择，而非只当背景名称。
4. 区分公共认知、专业知识、传闻和真实机制。角色可能误信一条规则；写清哪些人知道哪个版本，不让所有人同时获得作者答案。
5. 场景与地点提供可行动的空间：入口、出口、相对位置、可见与不可见区域、使用者、日常运作及发生冲突时的限制。只写金碧辉煌、阴森破旧无法支持调度。
6. 对幻想能力、科技或资源系统检查输入、输出、消耗、恢复与反制；对现实题材检查工作流程、身份关系和生活成本的自洽，不默认附加等级体系。
7. 用候选情节做规则压测：若每次遇险都可用同一规则无成本解决，就补足已被授权设计的限制或调整未来情节。已有正文规则不得为了新方案临时失效。
8. 扩写档案时分别给可用于人物行动的细节和冲突接口。相近组织说明立场、资源、行事方式的差别，避免只是换几个名称。

## Constraints

- 作者确认的规则优先于类型套路；提案与正史分开，改变既有规则需显式说明影响。
- 真实法律、医疗、历史、产业细节未经资料支持时注明待核实；虚构设定不能冒充现实常识。
- 设定之间冲突时保留双方来源并提出选择，不私自认定最新检索片段覆盖原设定。
- 不用大段世界说明替代场景中的可观察后果；也不要求所有设定都在本章解释。
- 此 Skill 提供创作方法；保存、采用、计费、发布和数据访问权限由调用能力决定。输出服从调用方 schema，不把方法示例变成新接口。

## Output

交付满足调用方数量和粒度的规则或设定档案。每项至少能说明其如何约束行动、产生冲突或改变选择；信息密度服从已确认展开计划，不靠术语列表凑字数。
