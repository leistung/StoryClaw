# story-summarization

## Description

按指定正文范围生成前情提要、阶段摘要和来源化事实记录，保留因果、人物状态与未解问题，供读者回顾或后续创作使用。

## Parameters

读取实际可用的章节、范围、摘要用途、目标长度和剧透边界。内部记忆、读者回顾与情节分析的细节需求不同；先确认覆盖范围而不是默认已读全书。

## Method

1. 明确来源覆盖：有哪些章和版本、是否缺章、哪些只是摘要或作者设定。摘要的范围不能超过已提供材料，不能把一次检索命中的片段包装成完整阅读。
2. 先抓事件链：人物目标、关键行动、回应、选择、结果及后果。按因果和必要时间组织，不逐句缩写，也不把章节标题连起来当摘要。
3. 提取真正变化的状态：人物所在、身份关系、物品归属、承诺、资源、风险和信息获得。只记录当前范围能支持的变化，保留变化发生的时间与来源。
4. 区分正文事实、角色说法、人物信念、推断和未来计划。某人声称见过凶手，只能证明其作出该声称，除非正文另有证据；不要把暗示或预测结算成正史。
5. 伏笔记录已投放内容、最近推进、已解释部分和仍待确认的问题。回收必须有实际结果，未来回收方向单列为计划；已有 ID 沿用，不编造索引记录。
6. 内部记忆保留支持关键事实的短原文、来源及限制条件，避免反复摘要造成信息漂移。把无依据评价改成观察，不把“他很可靠”代替“他按约归还了钥匙”。
7. 读者回顾按当前阅读点处理剧透，保留理解后文必需的人物与事件即可；内部摘要可更细，但也不能泄漏超出调用范围的未来内容。
8. 长范围先做分段记录，再合并重复实体和事件，保持时间顺序与状态更新关系。压缩普通经历时保留仍生效的承诺、限制与重要未解问题，不能只留最近的热闹事件。

## Constraints

- 摘要不能补写缺失章节、把计划当历史，不能从“没有提到”推出“不存在”。
- 引文需能在所给原文找到；没有来源编号时说明覆盖段落或章节，不制造 ID。
- 原文存在互相冲突的说法时保留来源差异，不擅自生成一个折中事实。
- 字数取舍服从用途与调用方约束，不用一套固定字数覆盖所有篇幅，也不宣称完整记住所有细节。
- 此 Skill 提供创作方法；保存、采用、计费、发布和数据访问权限由调用能力决定。输出服从调用方 schema，不把方法示例变成新接口。

## Output

读者摘要给自然、清楚的因果回顾；内部摘要给事件、状态变化、未解问题和可追溯证据。使用调用方 schema，只有 summary/facts/unresolved 时把信息填进这些字段，不套参考中的另一套结构。
