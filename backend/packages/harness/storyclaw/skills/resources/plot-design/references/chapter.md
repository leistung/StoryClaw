# 从章纲到可写的场景

## 场景卡的实际内容

记录“谁在什么处境下，要让谁做什么；对方为何不愿；主角用了什么办法；局面在结束时怎样变化”。旁观、等待或回忆也可以成立，但必须服务本章任务，不能靠增加人群议论扩充篇幅。

若调用方要求 SceneBeat 的 purpose/action/turn/result，就把因果填进对应字段；若只要求梗概，就写成自然段。不复制本参考的标题生成额外 schema。

## 一个连续事件怎样拆场

虚构例：上章已经查到账本页被换，本章目标是确认谁有机会接触原件。

- 场景入口：主角持有复印件，原件在值班室，管理员只答应下班前给十分钟。
- 第一行动：比对装订孔，确定换页发生在最近一次重新装订之后；不是再发现一次账目有问题。
- 阻碍与反应：管理员担心追责，拒绝提供出入记录；主角改为核对公开的借用登记。
- 新局面：登记证明熟人曾借走原件，但时间不吻合，主角决定先找熟人核实，暂不公开指控。

每一步都改变下一步能做什么。不要加“街头遇袭”来制造与证据链无关的热闹，除非已有因果支持。

## 接续检查

人物从上章的位置到本场需要多久；伤势是否影响动作；物品是否仍在持有人处；对白是否回应上一个问题；本章已经完成的动作是否被后场重新当作首次行动。光标插入、章中续写还要检查后文的固定衔接点。

## 输出前压测

用“因为……所以……”复述场景链。若只能使用“然后……又……突然……”，检查是否只有顺序而没有动因。不要为了形式给每场加一个反转；一次证据确认或关系上的小决定也可能足够。
