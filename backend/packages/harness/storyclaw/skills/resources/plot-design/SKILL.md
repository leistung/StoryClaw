# plot-design

## Description

设计当前章纲、场景任务单、主支线推进与伏笔回收，让事件由人物行动和后果连接；也用于诊断重复情节和推进停滞。

## Parameters

读取本章编号、已确认章纲或卷目标、前章结尾、相关历史证据、出场人物与知情边界。区分生成章纲、拆分场景、情节档案和分析报告；这些任务的粒度不同。

## Method

1. 先做起点核对：已完成哪些交易、发现、相遇和决定；当前人物身处哪里、手里有什么、此刻知道什么。把这些当作本章起始状态，不重新安排为新事件。
2. 用一个可观察的目标统领本章，例如拿到收据、获得某人的同意、阻止信息外泄。目标可以是情感或认知变化，但要通过选择和行动体现。
3. 设计有理由的阻力：对手的诉求、资源短缺、时间条件、关系中的隐瞒或规则边界。不要用所有人同时犯蠢、偶然听到全部真相来推动。
4. 组织事件链：尝试某种办法 → 引发回应或暴露问题 → 获得不完整的新信息 → 作出有代价的选择 → 留下结果。转折从前面行动、已备线索或合理误判中产生。
5. 分场时给每场入口、视角人物、目标、阻碍、具体动作、信息变化、出口。场景数由目标字数与事件复杂度决定；一场承担同一目标的连续博弈时，不按地点或对白数量机械拆碎。
6. 为情节线注明本章是埋设、推进、暂缓、兑现还是改变方向。已有伏笔沿用提供的 ID；新建议标为候选，用条件说明回收方向，不假装系统已登记。
7. 安排读者与角色的信息差。误导应来自可解释的观察或利益动机，揭露后能回看前文；不能靠叙述者突然隐去视角人物明知的关键事实制造廉价反转。
8. 检查章末状态差：物品归属、关系、证据、危险、承诺或认知至少有符合任务的变化。安静场景也可推进决定；不强迫每章都爆发冲突、反转或悬崖式结尾。

## Constraints

- 已确认章纲的场景拆分不能另造一条相反主线；发现章纲与正史冲突时指出来源与最小调整方向。
- 不把“计划回收”写成“已经回收”；未知回收章号可以留待定，不能杜撰精确节点。
- 字数、节拍和支线数量服从作者计划，不套固定百分比、固定转折数或必收所有伏笔的公式。
- 信息不足时保留影响因果的关键缺口；获准发散时可给明确标注的假设，不能将其冒充历史。
- 此 Skill 提供创作方法；保存、采用、计费、发布和数据访问权限由调用能力决定。输出服从调用方 schema，不把方法示例变成新接口。

## Output

章纲给具体梗概、接续点与不可违反的约束；场景任务单把目标和动作落实到每场；情节档案说明参与者、前提、事件链和结果；分析报告附证据及调整理由。只填调用方存在的字段，不把过程清单附在严格 JSON 外。
