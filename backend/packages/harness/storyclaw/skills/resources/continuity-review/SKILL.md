# continuity-review

## Description

对照正文、确认设定和来源证据审查人物、时间、物品、规则、知情、伏笔及重复事件，给出可核对的问题与最小修复方案。

## Parameters

读取待审版本和范围、可用历史、人物事实与信息边界、相关章纲及来源标识。注明缺失章节或检索错误；区分整章审查、局部修改复核和全书阶段检查。

## Method

1. 固定审查基线：当前正文的版本与范围是什么，哪些是确认设定，哪些是未来计划、传闻或模型提炼候选。版本不一致的检索记录不能直接充当当前正史。
2. 按人物、时间地点、物品资源、规则与能力、信息获得、事件承接、关系承诺与伏笔做定向核对。优先检查本章新增或改变的事实，不把所有细节平铺成无依据的问题清单。
3. 每个疑点寻找两端证据：本章具体说法或行为，与此前事实、规则或另一时点的说法。记录实际提供的章号、来源 ID、片段；没有行号时不要编造行号，没有另一端时标为资料不足。
4. 判断是否存在合理解释：别名、时间推进、回忆、梦境、角色误信或谎言、信息转述、此前有依据的例外。不可只因人物行为与性格标签不符就判定崩人设。
5. 检查人物知情路径。客观事实成立，不代表视角人物已经知道；秘密被谁亲见、何时转述、哪些只是猜测，分别核对。人物的错误信念也不等于世界状态改变。
6. 检查事件是否被重演：对比行为主体、意图、对象、动作、结果和人物认知。重复关键词或必要回顾不自动构成问题；换词再次完成相同交易也不能漏掉。
7. 对问题分清确定矛盾、疑似冲突、证据不足和风格建议，并说明影响。硬冲突与节奏、文风意见分开，不能用同一种严重程度逼迫所有建议通过。
8. 给最小修复：改一句、补信息来源、调整动作顺序或确认缺失设定。存在多种解决方向时写清代价；不未经允许自动改正文或替作者决定重大真相。
9. 检查修复建议本身是否引入更大问题。承诺只覆盖已审范围；没有发现问题表示“现有证据下未发现”，不等于全书一致性得到保证。

## Constraints

- 未检索到不等于没有发生；缺证据不等于确定矛盾，模型置信语气不能替代来源。
- 作者规划的事件不能证明正文已经发生；原文引述必须来自所给文本，不伪造章节、行号或台词。
- 伏笔久未回收不自动构成硬伤，需有期限、阶段承诺或已结束的结构依据。
- 只审查作者允许的文本范围；缺少另一端时说明需要核对什么，而不是凭空补前史。
- 此 Skill 提供创作方法；保存、采用、计费、发布和数据访问权限由调用能力决定。输出服从调用方 schema，不把方法示例变成新接口。

## Output

按调用方的报告格式输出审查范围、问题类别、两端证据、影响及可操作建议；如 schema 不支持单独状态字段，在说明中表达“疑似/缺证据”。只写实际发现的问题，可返回无问题结果，不为凑审查维度制造错误。
