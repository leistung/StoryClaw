# 从设定到完整小说

## 作品目标

《借火人间》：玄幻背景中的窑工家庭，在三十余年间面对寿火契约、债务、迁徙和亲人的离去。力量只改变生活条件，不替人物承担代价。四卷各十章，分别围绕窑口、欠火、过冬、还火推进；最终解决火契重复计息的证据与制度问题，不靠复活或突然获得神力收尾。完整可执行设定在 cases/borrowed-fire.json。

## 数据分工

PostgreSQL 是事实来源：用户、书籍、卷章、正文、设定、消息、积分流水。图片应保存对象存储引用与元数据，不将图片二进制塞入向量库。

Milvus 保存分段正文向量，用于根据当前写作任务召回历史原文；必须带 book_id 和 chapter_id 限定范围。Neo4j 保存抽取的人物、地点、物件与关系，用于补充实体关系检索。向量与图均为可重建索引，不能替代正文和编辑后的正式设定。

长篇不能只把“前章摘要”当记忆。需同时使用：固定规则、当前章大纲、当前场景目标、前章摘要、滚动已发生事实与相关原文。未来大纲只是计划，不能作为已经发生的事实。人物生死、时间、所在地点、持有物和伏笔最好进一步结构化；目前台账为可读文本，不宣称已经具备严格时态事实推理。

## 生成步骤

1. 认证现有用户，按实例标记创建或找回作品，写入固定人物和世界规则。
2. 大纲每批最多十章，传入先前大纲以维持全书因果；严格校验 JSON、章号、标题和梗概；生成前注入正式设定，生成后仍需审阅姓名与年代。本实例经人工核对修正了父亲姓名及17岁到50岁的时间节点。全部通过后才保存，失败不使用占位模板充数。
3. 创建四卷与四十个空章节。每章生成三到五个场景，明确人物、地点、目标和字数。
4. 按顺序写章，提示中附当前场景和边界。第一章覆盖 SSE，第二章覆盖批量接口，其余覆盖普通接口。
5. 从服务端读回正文，检查字数、段落、占位文字、重复正文。失败至多三次重写；备份旧稿，已验收前章不自动覆盖。
6. 调用入库接口，确认片段已保存，再实际查询验证。生成最近三章摘要更新连续性台账，每五章做一轮一致性检查。
7. 覆盖润色、续写、灵感、标题、场景、对白、阅读配置、人物与情节分析、分享接口。
8. 整本重新读取，检查四十章、至少十万字、无重复哈希、知识库索引与图实体、检索来源范围及服务端导出完整性。

## 当前边界与后续实现

这套测试是可恢复的客户端工作流，并非服务器后台任务队列。生产版应增加持久化 job/step、幂等请求键、取消、超时、重试与积分预占/结算；浏览器断开不应中止任务。

当前一致性报告属于模型建议，脚本保存报告，不自动保证其中问题全部修复。生产版应将严重问题结构化为阻塞项，按人物事实和伏笔状态决定重写范围，并在前章改动后标记后续摘要和索引失效。

正文变更会标记知识库待更新；现有索引、实体抽取与关系不能等同于严格版本化的完整事实账本。还需处理删除旧实体、冲突消解、来源追踪与图索引版本。图检索成功不能证明每条关系正确。

全量分析使用按章节分配的首尾片段与摘要，受上下文预算限制，不是把十万字全文完整送入每次审稿。人工应审核人物弧线、跨卷时间、伏笔兑现和结局，再安排有针对性的修订。

模型调用的输出预算按短片段单独限制。润色、续写不使用整章长度审核；整章同时检查过短与过长。辅助提示词的示例占位文字不参与 Python 字符串模板插值。自然语言检索支持问题包含实体名称的情况。
