# 批量生成多章写作指南

## 适用场景
- 新书开荒：从第 1 章一次性生成前 3-5 章作为试读
- 日更维护：选定起止章号，批量产出当日更新内容
- 续写补章：大纲已有但正文缺失的章节段

## 关键参数

| 参数 | 说明 | 示例 |
|------|------|------|
| start_number | 起始章号 | 1 |
| end_number | 结束章号（与 count 二选一） | 5 |
| count | 生成章数（与 end_number 二选一） | 3 |
| skip_existing | 跳过已有内容的章节 | true |
| thread_id | 复用对话线程（可选） | abc123 |

## 章节衔接规则

1. **前文摘要传递**：每章生成后，取正文末尾 600 字作为下一章的 `prev_chapter_summary`，保证人称、时态、场景连贯
2. **大纲节点匹配**：从 `outline.volumes[].chapters[]` 中按 `number` 字段提取当前章的 `title` 与 `summary`，注入 Writer 上下文
3. **自动取名**：若章节标题以"待定"结尾且大纲节点有 `title`，生成后自动替换
4. **失败隔离**：单章生成失败不影响后续章，错误信息写入 `items[].error`

## 质量控制

- 单次批量不超过 20 章（API 层强制限制）
- 每章独立走 Writer-Reviewer 循环（字数 < 目标 80% 触发重试，最多 2 轮）
- 建议先跑 `outline-planning` 生成完整大纲，再批量写作，避免情节跑偏

## 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 章节内容重复 | prev_summary 未正确传递 | 检查 `chapters_by_num` 是否按 number 排序 |
| 人称前后不一致 | 跨章上下文丢失 | 缩小批量范围，或在大纲中明确 POV |
| 标题仍为"待定" | outline_node 未命中该章号 | 检查大纲 JSON 的 number 字段类型 |
