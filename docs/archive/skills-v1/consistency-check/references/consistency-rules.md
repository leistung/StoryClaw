# 一致性检查规则与维度

## 输出 JSON 结构

```json
{
  "issues": [
    {
      "dimension": "character|timeline|worldbuilding|foreshadowing|naming",
      "severity": "high|medium|low",
      "chapter": 5,
      "description": "具体问题描述",
      "suggestion": "可操作的修复建议"
    }
  ],
  "summary": {"total": 3, "high": 1, "medium": 1, "low": 1}
}
```

## 五大检查维度

### 1. character（人设一致性）
- 性格是否前后矛盾（如内向角色突然外向）
- 价值观是否无因转变
- 能力是否超出设定（无金手指却做超常事）
- 称谓与身份是否匹配

### 2. timeline（时间线）
- 事件先后顺序是否合理
- 季节/年龄/时间跨度是否矛盾
- 回忆与现实的时序是否清晰
- 并行事件的时间锚点是否一致

### 3. worldbuilding（世界观）
- 地理/组织/势力设定是否前后一致
- 规则体系（魔法/科技/社会）是否自洽
- 专有名词是否统一拼写
- 历史背景是否有冲突

### 4. foreshadowing（伏笔回收）
- 已埋伏笔是否有回收
- 回收内容是否与埋设时一致
- 是否有"伪伏笔"（提及后完全遗忘）
- 回收时机是否合理（不过早不过晚）

### 5. naming（称谓一致性）
- 角色姓名是否全程统一
- 称呼关系是否随关系变化合理调整
- 地名/物名/招式名是否一致
- 昵称/全名/官职的使用是否合语境

## 严重程度定义

| 级别 | 标准 | 示例 |
|------|------|------|
| high | 逻辑硬伤/人设崩塌 | 主角名字前后不同 |
| medium | 明显瑕疵但可补救 | 时间线有小偏差 |
| low | 细节瑕疵/风格不统一 | 称谓偶尔不一致 |
