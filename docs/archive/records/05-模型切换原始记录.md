# 测试模型与额度降级

> 历史归档：保留当时方案或验证结果，不代表当前实现。现行说明从[阅读导航](../../00-阅读导航.md)开始；文中旧命令不应直接照做。

当前默认顺序：`glm-4.5-air` → `glm-5.3-flash`，共用已有智谱 OpenAI Chat Completion 接口及加密密钥。旧模型配置、密钥保留，旧文本模型在本次测试配置中停用；向量模型独立配置，未替换。

## 配置位置

- `backend/config/models.yaml`：新环境初始目录，主模型的 `fallback_models: [glm-5.3-flash]`。
- `backend/config/pricing.yaml`：平台测试积分费率，不代表智谱人民币价格。
- 已运行环境优先使用 PostgreSQL 平台配置；运营中台「平台模型」可以选择额度不足后的降级模型。
- `backend/app/services/platform/test_models.py`：显式测试配置迁移，复用现有加密密钥；不会把密钥打印或写进源码。
- `backend/app/services/platform/llm.py`：读取配置和价格、解密、向 Harness 提供惰性模型工厂。
- `backend/packages/harness/storyclaw/models/llm.py`：真实客户端与供应商参数适配。
- `models/fallback.py`：降级执行策略；`models/metering.py`：逐模型调用计量。

## 行为约束

1. 仅上游明确返回 HTTP 429、错误码 `1113` 或 `insufficient_quota` 时允许切换。
2. 最多两个模型，每个请求最多切换一次。普通限流、鉴权失败、超时、预算不足、作者取消、参数错误都直接停止。
3. 流式调用一旦返回任何 chunk，就不再切换；已有候选保留，避免混合两款模型的输出或重复执行工具。
4. 每次供应商调用独立预留和结算，按实际模型和当时价格快照记账；备用模型也受作者预算约束。
5. 失败不会自动恢复旧计划、自动采用正文或发布作品。
6. [智谱官方文档](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)规定 GLM-5.3-Flash 的 `thinking.type` 只能为 `enabled`。客户端强制启用，temperature 使用1。设置较小 max_tokens 时，思考会占用输出预算，正文可能很短；章节生产仍需足够预算及完整性审阅。

## 运维与探测

```bash
# 显式切到两款测试模型（需已存在 GLM 加密密钥及管理员）
docker compose --env-file .env -f deploy/docker-compose.yml exec -T backend python -m app.ops_cli configure-test-models
# 刷新 API、Worker 内存中的平台配置
docker compose --env-file .env -f deploy/docker-compose.yml restart backend worker
# 有上限的真实探测，每次最多5平台积分，包含一次文本及一次向量请求
docker compose --env-file .env -f deploy/docker-compose.yml exec -T backend python -m app.ops_cli model-check --model glm-4.5-air
docker compose --env-file .env -f deploy/docker-compose.yml exec -T backend python -m app.ops_cli model-check --model glm-5.3-flash
```

2026-10-25 实测：Air 文本及向量通过，2积分；Flash初次禁用思考返回400/1210，修正后文本及向量连通，4积分。Flash的2048输出预算主要用于思考，正文很短；本次不将其计作长章节验收。额度降级用受控模拟429测试验证，没有刻意耗尽真实账户额度。
