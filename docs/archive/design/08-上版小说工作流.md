# StoryClaw 小说工作流与 AI 架构（维护主文档）

更新时间：2026-10-25。本文是创作流程的主说明；默认连载的最新规则见第 9 节，优先于早期全量规划描述。状态以实现清单和测试为准，设计目标不等于已上线。术语中的“文档”是结构化创作档案，默认存于 PostgreSQL，不要求在服务器生成一堆 Markdown 文件。

## 1. 三层边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| frontend | 编辑、确认、任务进度、检索来源、错误与引导 | 拼系统提示词、持有模型密钥、直接访问向量库 |
| backend | HTTP/鉴权、权限隔离、SQL 读写、任务租约、版本快照、积分、注入数据适配器 | AI 提示词、模型输出修复、生成策略、检索编排 |
| backend/packages/harness | LangChain/LangGraph、提示词、结构化输出、选题导演、创作设计、场景规划、写作/审核、RAG、切片、Embedding、图谱、上下文预算 | 导入 FastAPI、SQLAlchemy 或 backend，决定用户权限与扣费 |

包通过配置注入模型客户端、数据读取和只读工具适配器。模型返回领域结果与 token 用量；后端验证权限并在事务中保存结果、积分流水和任务状态。

## 2. 创建一本书需要哪些档案

| 档案 | 必填程度 / 内容 | 依赖及维护方式 |
| --- | --- | --- |
| 开书卡 | 必需：书名、题材、简介、主角、暂定全书规模/每章字数 | 聊天讨论后人工核对；总量可调整，不等于一次生成量 |
| 故事总纲 | 必需：核心冲突、主角目标、主要转折、阶段结局/开放方向 | 参考开书卡和已写设定；长连载允许后段保持粗略 |
| 卷纲与章纲 | 当前阶段必需：卷名、阶段目标、章号/标题/梗概 | 结构化 Outline.volumes；总纲保存在 overview，卷目标保存在 volumes[].goal；旧大纲可补写这些字段 |
| 世界观档案 | 按题材：时代地理、社会制度、力量规则、资源限制、禁忌、文风/叙事边界 | 手写或 AI 草拟，参考已确认大纲；现实题材不强行生成修炼体系 |
| 角色卡 | 核心角色优先：身份、欲望、恐惧、底线、关系、成长弧 | 参考大纲+世界观+现有角色；后续新增配角即可，不必预先造齐所有人物 |
| 场景与物品 | 按需：空间规则、距离、关键道具归属和使用代价 | 参考世界观、角色、大纲与已发生正文 |
| 情节/伏笔档案 | 按需：主支线、埋设、推进、回收位置 | 参考已确认大纲、现有角色设定和历史正文；未来规划与已发生事实分开 |
| 单章场景任务单 | 可选：3–5 场景，目标、阻碍、转折、地点、人物、字数 | 参考当前章纲、前章结尾、设定、历史检索；不是必须按按钮走完的仪式 |
| 章节正文与修订 | 必需：草稿→人工确认正文 | 人写/AI 写都可以；重写保存版本，不能覆盖并发编辑 |
| 故事记忆索引 | 为后续写作服务：历史片段、实体关系与来源 | 从确认正文构建，不是新的原稿，也不自动变成作者角色卡 |

最小起步集为开书卡、可用的大纲和核心主角信息；世界观、配角、场景、物品可随写作补齐。不是所有题材都需要同样多的档案。

## 3. 推荐状态机

开书资料 → 大纲草稿 → 作者确认大纲 → 世界观/角色/情节设计草案 → 作者采用并编辑 → 当前章纲 → 可选场景任务单 → 正文草稿 → 审阅确认并更新记忆 → 索引成功 → 下一章。

- 作者可以提前手工构思任何设定；AI 的正式档案生成和情节/章节规划以已确认大纲为基础。
- 同书一次一个后台任务。切换标签、关闭浏览器不取消；服务进程重启可能中断执行，任务会失败，不自动重复付费调用。
- 保存/重生成大纲清除确认；已写正文保留。设定变更后需作者检查受影响章节，当前不自动重写全书。
- 草案采用是明确操作，不用生成结果悄悄覆盖既有设定。同名档案保留原值并提示跳过。
- 人工手写不强制先做所有 AI 步骤。

## 4. 写下一章实际参考什么

1. 后端校验账号、作品、目标章节，读取开书卡、当前章纲、世界观/角色/场景/物品/情节、前章正文、可用历史章节列表。
2. 包内上下文服务定位本章大纲，取前章结尾（当前是文本截取，不称为完整的 AI 摘要）。
3. 包根据章标题和梗概生成检索查询，调用 Milvus 语义召回与 Neo4j 关系查询；仅允许本书、本用户、已成功索引且章号早于当前章的正文。
4. Writer 还有 query_setting、query_memory、get_outline、get_prev_chapter、get_book_meta 只读工具，最多有限轮调用，按需补查；工具不是装饰，结果作为 ToolMessage 进入写作调用。
5. 上下文去重、限长、附来源，再生成草稿和审核意见；输出由后端保存为章节新版本。
6. 检索命中是相关片段，不代表读到了全部历史字句。上章结尾负责接续，向量负责语义回忆，图谱负责关联事实，作者设定优先。不能承诺零矛盾。

索引失效/不可用必须显示，严格连贯写作不应无提示继续。现有工具可展示检索错误；新增上下文状态也随结果暴露，不将失败伪装成“没有相关内容”。

## 5. 正文何时进入向量和图数据库

- 点击保存/AI 生成完成：PostgreSQL 立即保留正文；修改后 rag_status=pending，旧索引不再参与写作检索。
- 作者执行“确认正文并更新记忆”：后台 index 任务获取正文快照及哈希，包去除富文本、切片、Embedding 写 Milvus，并从全章分段抽取实体/关系写 Neo4j。
- 仅两种持久索引写入成功、数量通过检查且正文未改变时，后端标 loaded。失败保留 pending 与任务错误，可重试；不把内存降级当作生产入库成功。
- 修改正文再次变为 pending，需要重新确认并索引；删章节后业务过滤撤销可见性。当前索引物理清理与版本清单不是完整的跨库事务。
- 纯 AI 批量写作也不能跳过事实确认。当前选择可追踪的逐章流程，不在生成完成后偷偷发起不计费/无任务的抽取链。若未来提供无人值守模式，应独立设置自动审核门槛、预算、失败暂停及回滚；本轮不宣称已实现。

## 6. 常见场景

| 场景 | 行为 |
| --- | --- |
| 已有大纲粘贴进来 | 手工维护卷/章节点，保存并确认；没有要求必须由 AI 起草 |
| 只确定开头的百万字连载 | 全书总量是目标；远期先粗纲，近期细纲；默认已支持总纲/阶段与逐章规划；旧全量模式仍限制 500 章，不把 3000 章输入当成全量自动规划支持 |
| 上章已写但没入库 | 直接上下文能看到上章结尾，不能声称完整历史记忆已可用；先确认上章并更新记忆 |
| 修改历史章节 | 旧索引不可见；重建后检查后续章节，系统不会悄悄重写后文 |
| 图库写失败、向量成功 | pending，不开放半成品给写作；检查任务错误再重试 |
| 生成角色与手工卡同名 | 不自动覆盖；采用时跳过，并显示跳过数量 |
| 新提案参考了旧大纲 | 采用前校验大纲哈希，变化则要求重新生成/核对 |
| 刷新/重复提交 | 服务端任务与请求编号去重，前端恢复服务端状态 |
| 改 Embedding 模型或维度 | 必须重建并避免跨维度混检；完整模型版本清单仍待实现 |
| 世界观与正文矛盾 | 作者规则优先，提示并人工决定修订；不让模型自动改规则迁就草稿 |

## 7. 实现与待补边界

本轮已实现：包内选题导演/格式解析/场景规划/上下文组装与 RAG；世界观档案 CRUD；世界观/角色/情节结构化 AI 草案与显式采用（同名不覆盖、重复采用幂等、大纲变更拒绝）；正文确认哈希入库和历史记忆就绪门槛；全章分段实体抽取；禁止未跟踪的设定自动同步。后端新增或保留的适配器只负责 SQL、权限、积分和任务。

已有正文版本、持久任务、成功索引过滤和目标章节边界；尚不具备稳定实体 ID/别名、完整时序事实、索引 manifest 原子切换、自动后文影响分析、无人值守全书生产或完整书稿文件导入。这些不能写成已经上线的功能。

后续优先级：索引版本清单 → 章摘要/卷摘要与伏笔状态 → 分阶段扩纲 → 冲突证据与影响章节 → 可配置自动化模式。检验重点是隔离、来源、失败可见、旧版过滤和人工确认，而不只是“模型输出了文字”。

| 总纲、卷纲、章纲与确认结构校验 | `outline.py`, `prompts.py`, `workflow.py` | `api/outlines.py`、`services/planning.py` |

| 写作上下文、前章结尾与双库检索 | `writing_context.py`, `context.py`, `nodes/writer.py`, `nodes/tools.py`, `rag/` | `services/skill_loader.py` SQL 读取、`services/agent_tools.py` 只读数据工具 |
| 确认正文与索引任务 | `rag/service.py`, `chunker.py`, `embedding.py`, 两库 store | `api/rag.py` 校验正文哈希、`services/jobs.py` 持久队列 |

旧的 backend AI 模块仅保留兼容导入或停用钩子，不再包含模型调用和提示词。包声明独立依赖并有导入边界测试，禁止依赖 backend/FastAPI/SQLAlchemy。后端不得重新添加系统提示词或自行调用模型；新 AI 能力从包暴露函数，API 只传领域数据、接收领域结果。

隔离测试覆盖：草案不自动入作者档案、采用幂等/权限/同名保护；未确认正文不能入库；前章 pending 拦截下一章，loaded 放行，改稿重新拦截；全章尾部事实参与抽取；来源章号正确；双库故障可见；包导入边界。模型调用与外部库响应在自动化回归中使用桩，不把桩测试当作供应商端到端验收。生产 Milvus/Neo4j 的索引状态可在故事记忆页面另行核对。

索引阶段现有模型/Embedding 用量未完整进入单独计费流水，完整索引计量与预算仍待补，不能将写作结果中的 token 数当作所有上游调用总账。

测试脚本兼容：`backend/evaluations/run.py` 不再在无变化时反复保存大纲、清掉确认；直接入库也提交当前正文哈希。默认要求工作台人工确认；仅隔离测试可显式传 `--approve-test-output`，授权脚本采用通过本地规则的测试输出。这不是产品的无人值守模式，也不代表文学质量或事实已人工验收。本轮没有运行付费长篇生成。

最终验证：40 项后端回归、4 项前端测试与类型检查/构建通过；运行中容器导入和 `/health` 正常，Milvus 与 Neo4j 实际连接均成功。测试不代替真实模型的文学质量验收；没有自动确认或改写现有作品。

## 9. 连载规划与逐章依赖（2026-10-25 第二轮修订，以本节为准）

此前“开书时先生成所有章纲”的实现与连载需求不符。本节替代上文关于全量章纲的默认假设；旧模式保留为可选“定稿·全书章纲”，不自动改动已有作品。

### 9.1 三层规划

1. 故事总纲：核心冲突、主角目标、世界规则、长期悬念、可调整的收束方向。确认方向，不确认必须写多少章。
2. 近期阶段/卷目标：阶段要达到什么变化、要解决什么问题。可以新增、调整阶段，不强制把 10 章拆成一卷，也不要求远期情节写细。
3. 当前章纲：仅在准备写第 N 章时拟订目标、阻碍、行动、转折、结果、章末接续点和连续性约束。作者确认后才生成正文。

默认新生成采用 `planning_mode=serial`，生成总纲和阶段，不生成全书章节数组。`target_chapters`/`target_words` 是可调整预估，不是连载终止条件；可以继续新增章节。每章规划存在内部 workflow 档案中，独立保存与确认，不往未来章节批量填情节。未确认的规划和已发生正文严格分开。

### 9.2 每个写作场景到底读取哪些档案

| 场景 | 必须参考 | 不能当作已发生事实 | 门槛 |
| --- | --- | --- | --- |
| 写第 1 章 | 开书卡、确认总纲与近期阶段、已有世界观/角色、确认的第 1 章情节；可选场景单 | 远期阶段、未来伏笔回收、模型自行猜测的前史 | 无前文，无需虚构历史检索；先确认本章情节 |
| 写第 2 章 | 上述稳定档案、第 2 章情节、第 1 章结尾、第 1 章成功入库的相关片段/关系 | 第 1 章旧稿、未确认章纲、尚未发生的未来情节 | 第 1 章正文存在且入库；第 2 章情节依赖未过期 |
| 写第 N 章 | 稳定档案、当前阶段、第 N 章情节、上章结尾、早于 N 的有效索引；只读工具补查 | N 及之后正文、待复核章节索引、过期场景单 | 所有已写前文须复核入库；紧邻上章不能为空 |
| 续写当前章片段 | 当前正文、当前章纲、已有设定和前文证据 | 自动开启下一章、擅自改变确认的方向 | 作为编辑片段，保存时使本章旧索引失效 |
| 修改当前章情节 | 当前总纲、设定、前文；保留原正文 | 自动把新计划说成正文已发生 | 保存并确认新章纲；已有本章/后文标待复核 |
| 修改第 K 章正文 | 原稿、修订版本、当前规则 | 让后文自动变成一致 | K 章 pending；K 之后已有正文 pending + 影响通知；不自动重写 |
| 改角色/世界观/总纲 | 作者修改内容、已有全文的影响范围 | 自动覆盖已写正文或推断精确影响范围 | 保守要求所有已写章节复核；精确语义影响分析待补 |
| 只增加未来一章 | 稳定方向与当前前文 | 要求补齐整个远期大纲 | 新增空白章节，按需拟订这一章，不修改已发生事实 |
| 重新生成单章情节 | 原计划、作者新指令、最新前文与设定 | 偷偷采用模型新结果 | 草稿先保存，人工确认；正文不自动覆盖 |

“上章摘要”目前是去标签后的结尾截取，不是模型生成的完整章节摘要。真正的章摘要/卷摘要和伏笔状态机仍是待补能力。向量召回也不是穷尽全文，因此不能声称系统永远记得每个细节。

### 9.3 版本依赖与失效

章纲绑定参考指纹：总纲/阶段内容、作者设定、前文逐章内容哈希、开书关键资料。内容变化后，GET 章纲即显示 stale，不能直接写作；可重新生成，或作者核对后手动保存并确认。

- 连载模式总纲哈希只覆盖总纲和阶段，不因为添加未来的章节点就取消整本书方向确认。
- 场景单额外绑定本章章纲哈希。换章纲后旧场景单不再注入 writer。
- 正文/标题变更、恢复旧稿、删除历史章触发后文索引停用与影响通知。作者必须核对后重新确认入库，不能仅重建前章就默认后文正确。
- 改稿后的历史正文保留，版本历史可查看；索引只撤销可见性，不等于删除原文。
- 影响提示属于保守依赖分析，不代表 AI 已证明后文存在矛盾；不相关的后文也可能需要一次人工确认。
- 自动生成写回前重新检查参考指纹和本章正文哈希，防止生成期间前文或设定变更导致迟到结果覆盖。
- 正式后台任务同书互斥，关键资料修改受限；旧的直接 HTTP 生成入口仍保留兼容，关键写回有版本保护。连载模式禁止旧批量写作接口跨过逐章确认。

内部规划/影响通知使用 ConfigEntity 的 `workflow` 类型，受接口权限控制，不作为作者世界观或情节卡注入模型，也不能通过公开设定 CRUD 篡改确认标记。

### 9.4 审计发现与处理

| 问题 | 原风险 | 本次处理 / 边界 |
| --- | --- | --- |
| 全书预生成章纲 | 连载被错误锁死，后期修改成本高 | 默认改为总方向+近期阶段+逐章确认 |
| 旧章纲绑定旧前文 | 继续生成可能沿用已废弃因果 | 依赖指纹过期检查，明确重新确认 |
