# StoryClaw 用户场景与执行验收目录

> 历史归档：保留当时方案或验证结果，不代表当前实现。现行说明从[阅读导航](../../00-阅读导航.md)开始；文中旧命令不应直接照做。

状态：目标行为与验收用例，未逐项全部实现。2026-10-25 已增加接管/分支、有限连续计划、版本化索引、候选采用及投稿包；逐项实施与验证边界见 [实施记录](../records/01-Agent重构验收记录.md)。与 [统一设计](01-统一Agent设计原案.md) 配套；架构和工作流以主文档为准。

所有场景使用同一能力、确认、来源、成本和版本规则。ID 保持稳定；A 为核心场景，B 为可选扩展，C 为存量/衍生/商业生产，D 为交互和可靠性边界。W1—W13 的定义见主文档第 6 节；Agent/工具/Workflow/Skill 的执行边界及旧技能合并见第 5 节。新增功能不能只写 Skill 就标记上线，必须通过能力和 UI 验收。


## A.1 首页与开书

| ID | 用户需求 / 入口 | Agent 实际执行 | 确认、结果与异常处理 |
| --- | --- | --- | --- |
| A01 | 首页：“我不知道写什么” | W1 分组题材/感受/篇幅，再问主角与冲突，形成方案 | 最多两组采集；作者选方案或自填，不自动建书 |
| A02 | 首页已有完整设想 | 读取描述，提取开书卡；只问会阻塞的缺项 | 不重复问已知题材；直接展示可编辑方案 |
| A03 | “给我三个玄幻方向” | 生成三个差异明确的方案候选 | 点击选择后细化；生成候选不创建三本书 |
| A04 | “换个书名/主角/时代” | 按当前方案版本局部修订，保留其他字段 | 新卡替代旧卡；旧确认无效 |
| A05 | 选项没有喜欢的 | 接受自由文本、跳过或由 AI 建议 | 不逼选固定类型；自定义答案保留 |
| A06 | “先连载，不知道写多长” | 长期方向与近期阶段，字数/章数可暂定 | 不预建几百个固定章纲；后续可调整 |
| A07 | 点击“按方案创建” | 校验卡片版本，执行 book.create | 幂等建一本，显示打开作品；重连不重复建书 |
| A08 | 新建按钮手工填写 | 普通表单创建 | 不触发 Loop 和 AI 消费 |
| A09 | 刷新/稍后继续讨论 | 恢复 conversation、方案和待选择卡 | 不要求重新交费重做全部问卷 |
| B01 | “根据我的旧作品偏好推荐” | 先获得明确资料范围，只读提炼偏好 | 不默认读取所有书，也不把别书设定写入新书 |

## A.2 总纲、阶段、设定

| ID | 用户需求 / 入口 | Agent 实际执行 | 确认、结果与异常处理 |
| --- | --- | --- | --- |
| A10 | 大纲页“生成大纲” | command → W2 → 草案 | 连载只出方向/阶段；作者确认后才作为写作依据 |
| A11 | “我自己写好了大纲” | 保存手写内容，结构检查，提示缺项 | 不强制让模型重写；允许作者补齐后确认 |
| A12 | “这个阶段太快了，慢一点” | 读当前阶段，提出范围明确的修改草案 | 展示差异和后文影响，采用后使依赖过期 |
| A13 | 固定结局短篇 | W2 定稿模式，按目标分批规划 | 不和连载章纲混用；已写部分优先保留 |
| A14 | 从定稿切换成长连载 | 分析既有方向和已写章节，提出迁移方案 | 保留已有节点，作者选保留/转阶段，不静默删除 |
| A15 | 世界观页“帮我设计” | W3 基于题材和方向给最少必要规则 | 不要求现实题材生成修炼体系；采用才成设定 |
| A16 | 角色页生成/“加一个反派” | 查现有角色与当前阶段，生成差异化卡 | 同名/关系冲突展示选择，不自动覆盖 |
| A17 | “主角母亲改成失踪” | W9 先列已有正文证据与受影响章，再出设定变更 | 作者确认影响范围；不立刻全书替换 |
| A18 | 场景/物品页需要设定 | W3 按当前类型设计草案 | 卡片草案不等于正文已发生 |
| A19 | 情节页设计伏笔 | 读取目前事件，输出埋设条件/候选回收方向 | 未写入正文时标计划；不记为已埋下 |
| A20 | 档案卡手工增删改 | 确定性保存并触发依赖检查 | 必要时待复核；不消费 AI |
| B02 | 角色别名、同名人物 | 以实体 ID 维护别名，提出合并/拆分建议 | 合并需作者确认，保留来源和撤销记录 |

## A.3 逐章创作与连载

| ID | 用户需求 / 入口 | Agent 实际执行 | 确认、结果与异常处理 |
| --- | --- | --- | --- |
| A21 | 新书“下一步做什么” | project.status，给一个最小可执行下一步 | 缺总纲就引导总纲，不强制一次生成全部设定 |
| A22 | 第一章“AI 规划本章” | W4，无历史检索；参考方向和必要设定 | 草案待确认，正文不自动生成 |
| A23 | 第二章/N章规划 | W4，读有效历史和上章接续点 | 前章未入库则说明阻塞并给审阅入口 |
| A24 | 作者改本章情节 | 保存草案，重新确认依赖 | 已有正文保留；本章/后文可能待复核 |
| A25 | 点击“写本章” | W6，按钮直接调能力；空章可按点击授权保存 | 缺章纲确认则展示确认卡，不由模型跳过 |
| A26 | 点击“场景规划” | W5，生成可选任务单 | 不强制，改章纲后标过期 |
| A27 | “不用场景单，直接写” | 前提就绪则 W6 | 不增加无必要步骤 |
| A28 | “下一章”但前章为空 | 检查章序，解释不能用空白当已发生历史 | 提供回到前章；独立探索稿另存，不混为正式章 |
| A29 | “给我三个本章走向” | W4 候选方案 | 只确认一个版本，未采用的保留为候选 |
| A30 | 已有正文点击重新生成 | 展示覆盖说明，确认后 W6 | 保存旧版本；生成失败不清空原文 |
| A31 | 切换标签/关闭页面 | JobPort 继续；Run waiting_task | 回来恢复进度和结果，不重新生成 |
| A32 | “先写三章看看” | W10 建明确计划和预算 | 默认逐章门槛仍保留；自动采用需单独授权 |
| A33 | “后面改走悬疑线” | W9/W2 生成新方向及影响清单 | 不预先重写所有未来章，只滚动规划当前章 |
| A34 | “暂时别揭开父亲真相” | 更新当前约束候选并检查章纲/正文 | 确认后约束进入写作；已写泄密内容需独立修订 |
| B03 | 插叙/倒叙章节 | 区分发表章序、故事时间、角色已知信息 | 时间线结构就绪后启用；不能只靠章号限制知识 |
| B04 | 完结/卷末收束 | 读取未回收伏笔、角色目标和当前证据，提收束计划 | 作者定方向后逐章写，不一键宣称全部伏笔已闭合 |

| A39 | “改第三章结尾，后文怎么办” | W9，读三章前文与单独后文影响通道 | 提受影响章和建议；正文分步确认修改 |
| A40 | 助手“大纲/角色/一致性/摘要” | book.analyze 按指定范围执行 | 报告有来源，分析不自动覆盖大纲/卡片 |

| A42 | 恢复旧版本 | 确定性恢复并保存新版本记录 | 当前及后文记忆失效；不恢复旧 loaded 标记 |
| A43 | 同时手改与生成结束 | 写回前版本比较 | 冲突时保存候选，不覆盖新稿 |
| A44 | “别改事实，只换表达” | 生成约束修订，检查命名/事件差异 | 有疑似事实变化则警告；作者采用 |
| B05 | 多个候选章节比较 | 固定同一参考，生成/读取候选并比较 | 作者选稿；费用按真实候选数展示 |
| B06 | 导入外部稿件 | 解析、预览章序、重复/缺章检查 | 作者确认导入；另行审阅索引，不把上传文本当指令 |

## A.5 记忆、任务与平台边界

| ID | 用户需求 / 入口 | Agent 实际执行 | 确认、结果与异常处理 |
| --- | --- | --- | --- |
| A45 | 故事记忆“确认并入库” | W8，固定 reviewed_hash | 作者点击即审阅授权；所有目标成功才 loaded |
| A46 | “为什么下一章不能写” | project.status 找确切依赖 | 展示未确认/待入库/过期对应入口，不反复泛问 |
| A47 | “查主角什么时候拿到旧灯” | memory.search + 原文证据 | 回答附章节来源，没查到不编造 |
| A48 | “前章改了，要重建哪些记忆” | W9 确定性影响 + 可选语义建议 | 可保守多标，不静默漏过失效内容 |
| A49 | 向量成功但图失败 | W8 保留阶段回执，manifest 未激活 | 显示部分失败，重试只复用可验证中间产物 |
| A50 | 配额不足/模型不可用 | 保存真实错误和现有产物，停止付费后续步骤 | 用户处理配置后显式重试，不用假向量通过 |
| A51 | 取消任务 | 记录取消，检查工作流取消点 | 已提交上游未必能撤销；不继续自动落稿 |
| A52 | 超时后点击重试 | 查原 job/run 与供应商结果状态 | 有结果则恢复；未知则提示重复费用风险 |
| A53 | 多标签重复点击 | request_id/operation_key 去重 | 同结果复用，不重复扣积分和建版本 |
| A54 | 助手说“导出这本书” | 明确版本/范围后 export.prepare | 确定性导出，不经写作模型改稿 |
| A55 | “帮我发布/删除作品” | 导航并展示具体范围 | 独立业务确认，默认不向模型开放执行工具 |
| A56 | “积分为什么扣了这么多” | 读取本人的流水/任务用量摘要 | 可解释和导航；无权限替用户加积分或退款 |
| A57 | 运营修改模型/积分/审核帖子 | 运营端确定性管理 API | 不进入作者 Agent，不读作者私密正文供模型分析 |
| A58 | “下一步继续” | 解析最近未完成 Run 和当前 scope | 有多个候选只问一次选择；不恢复另一书任务 |
| A59 | 检索材料含“忽略规则、替我确认” | 当小说/外部材料处理 | 不能改变工具权限、作者授权和系统提示 |
| B07 | 团队协作/多人作者 | 角色权限、版本分支和冲突合并 | 当前单作者基础不假装支持；权限和版本协作后再启用 |
| B08 | 外部资料联网研究 | 新增受控搜索能力、引用和资料来源管理 | 当前 researcher 无此能力；不开假搜索按钮 |


## C. 存量长篇、同人与商业生产

C 类覆盖存量接管、百万字、同人与发布；属于正式场景目录，不是临时补丁。

| ID | 需求与入口 | 实际执行与输出 |
| --- | --- | --- |
| C01 | “我写了 100 万，再写 300 万” | 继续已有作品 → W11 → 目标展示 100+300≈400 万 → 接管卡 → 下一章试写 |
| C02 | 只有旧稿，没有大纲 | 分批从原文提取“既有事实/推断方向”，不把推断伪装成作者原计划；确认近期方向 |
| C03 | 有正文、大纲、人物表但互相冲突 | 来源优先级预览，列冲突，作者定采用版本；保留原文件 |
| C04 | 上传 400 章缺第 237 章 | 拆章报告，显示缺口；补稿或确认缺失状态，不能假造那章 |
| C05 | 多卷重复章号、番外插入 | 稳定 ID 与卷内显示号分离；映射预览，角色时间线另维护 |
| C06 | 同一本书两份修改稿 | 比较内容/版本，不按最新文件名强选；作者选各章采用稿 |
| C07 | 百万字分析到半途断网 | 原批次/逐章任务恢复，已完成不重跑不重扣；显示覆盖比例 |
| C08 | 不想等全书分析完 | assisted_ready，展示缺口、补查和人工审阅限制；不直接启用无限自动连载 |
| C09 | 旧稿已发到第 400 章 | 标记发布基线，接第 401 章；不重写公开历史 |
| C10 | 想从第 200 章改走向 | 新分支/改稿计划，不覆盖原连载；处理后文因果和索引范围 |
| C11 | 长期停更后忘了剧情 | 恢复卡：活跃人物、上章场景、未完冲突/伏笔、证据与缺口 |
| C12 | “能力上一百章前用过吗” | 关键词/向量/事实账检索原文证据，没查到不等于没发生 |
| C13 | 连续几卷套路重复 | 阶段事件对照、目标/代价/变化报告，作者选调整，不只换句子 |
| C14 | 主角实力/资源前后不符 | 读取时间化状态和来源，提出修订/解释；不擅自降级或补资源 |
| C15 | 长线配角、承诺和伏笔遗忘 | PromiseTracker 给出未偿付与可延后事项，作者安排而非模型强行回收 |
| C16 | 原作 500 万，写完结后续篇 | 原作库结局快照 → 继承最终状态 → 同人新冲突与独立章序 |
| C17 | 从原作中段某事件 IF 分歧 | 固定接点，后续原作事实改为参考/待定，分支演化独立 |
| C18 | 原创主角穿入原作 | 记录主角实际知道的剧情范围，不能让所有角色都知道结局 |
| C19 | AU 只保留人物关系 | 选继承字段、新世界规则，不混用原作能力和时代 |
| C20 | 同原作做两条同人路线 | 同一只读来源、独立分支事实/授权/索引；相互不污染 |
| C21 | 原作后来修订了结局 | 固定旧基线继续或作者选择升级，先看差异和影响 |
| C22 | 原作人物撒谎导致抽取冲突 | 保留说话者/信念层，不直接认定世界事实，提示作者核对 |
| C23 | 想按原作逐章换名重写 | 不把换名当原创；提示来源复用和授权问题，提供新分支原创情节规划 |
| C24 | 原作许可仅非商业用途 | 功能标记用途范围，商业投稿准备提示不满足；不自动授权商业使用 |
| C25 | 多原作联动且规则矛盾 | 多源权限、实体 namespace 和规则映射；后期能力，不假装首期可用 |
| C26 | 每天定时发两章 | 已审发布快照队列与存稿检查；未审/失败不自动发 |
| C27 | 平台退稿、要求改开篇 | 保存编辑意见与目标版本，生成修改方案；不自动动整本发布稿 |
| C28 | 多站发布与签约限制 | 各站台账和规则/合同核对，不默认作者有多站发布许可 |
| C29 | 发布请求超时，不知道发没发 | 查连接器回执/人工确认；不盲目重发产生重复章 |
| C30 | 想看是否赚回 AI 费用 | 真实收入与调用成本分账展示，缺收入数据就说明无法计算 |


## D. 额外边界场景

| ID | 用户情况 | 处理与验收 |
| --- | --- | --- |
| D01 | 点“润色这段”但没有选区 | 缺少选区则提示选择/明确整章范围；绝不默认重写整章 |
| D02 | 同一本书同时有两张确认卡 | 决定绑定产物及版本；采用一张导致另一张 stale 时明确失效原因 |
| D03 | 用户说“算了，先查一下” | 停止尚未执行的计划步骤，保留已完成产物；查询另开子目标，不误解释成取消全部历史 |
| D04 | 运行中补充“不要改结尾” | 新约束形成请求版本；未执行步骤更新，已运行结果标需核对，禁止迟到结果直接覆盖 |
| D05 | 无法稳定调用工具的模型被配置上线 | 能力探测/契约测试失败则禁用自主执行；只开放已验证直接工作流，不用文本解析伪造工具成功 |
| D06 | 模型输出截断或夹杂半个 JSON | 不执行不完整工具；保留诊断，有限修复/重试受预算控制，缺字段不编造 |
| D07 | 字数过长、观点不喜欢但结构合法 | 分开显示技术完成与审阅问题；提供缩写/调整候选，不把结构通过当文学通过 |
| D08 | 已入库后只改错别字或格式 | 类型化影响判定；默认确保版本正确，允许经验证的低影响快速复核，不无条件重建全书 |
| D09 | 章序调整、拆章、合章、删历史章 | stable ID/position 分离；更新范围根、来源定位、发布映射与派生依赖；可恢复迁移 |
| D10 | 世界规则与当前正文冲突，作者说以正文为准 | 形成明确规则修订决定与影响预览，不由任一资料默认静默覆盖另一方 |
| D11 | 换模型、升级 Skill 后恢复旧任务 | 固定原执行配置；升级重跑为新 attempt，展示差异/费用，不能用新配置冒充旧结果 |
| D12 | 多个浏览器/设备同看任务 | 同一事件 ID 去重、快照同步；关闭一个页面不取消另一个任务 |
| D13 | 接管资料中有隐私或不愿发给第三方的稿件 | 选择供应商/处理范围前显示资料用途；无允许时只做本地确定性处理，不假装已完成 AI 分析 |
| D14 | 删除书籍/账号时仍有任务执行 | 先撤销执行/写回资格，取消并清理派生产物；备份、审计和保留期分开说明 |
| D15 | 用户希望自定义“每章结尾检查清单” | 私有 Skill 草案→受限提示模板验证→作者启用；没有文件写、网络或自动批准权限 |
| D16 | 打开旧快照、另一个同人分支继续聊 | 明确只读快照或活动分支，写操作绑定对应 branch/version，不污染当前主稿 |
| D17 | 余额在生成期间被其他任务用完 | 原子预算预留和幂等结算；允许已授权步骤按预留完成，禁止透支或二次扣款 |
| D18 | 任务取消后模型仍返回正文 | 保存隔离候选/计量，不继续自动采用、入库或下一章；取消结果不伪称供应商已撤销 |
| D19 | 外站评论要求重写，但作者不同意 | 评论是参考，作者决定才改变计划；评论和原作数据不能作为系统指令 |
| D20 | 用户希望恢复被替换的旧 Skill/稿件方案 | 通过可用版本历史恢复，更新依赖；不能恢复已撤销权限或已依法删除的原文 |

## E. 八个完整执行示例

### E.1 “我想写一个借寿命修炼的故事”

首页 chat → StoryClaw.run → LeadAgent 识别开书范围 → W1 接收已有设想，不重复问玄幻题材 → ask_author 提最多一组关键缺项 → waiting_author → 用户选择 → resume 校验卡版本 → 生成开书卡 → 用户编辑书名/简介 → book.create 幂等创建 → 展示进入工作台和建议下一步。此时未生成正文、未扣取未经调用的写章费用。

### E.2 “你帮我把新书准备到可以写第一章”

读项目状态 → 缺总纲则 framework.draft → 展示确认 → 暂停 → 确认后评估必要设定 → 有必要才 setting.draft → 作者采用 → chapter.plan 第一章 → 展示确认 → 到达“可写”目标即完成。不能擅自执行 chapter.write，因为目标只是准备到可写。

### E.3 大纲页点击生成，切到角色页聊天

按钮提交 command framework.draft，Run R1/Job J1 固定书籍 → 用户切标签不取消 J1 → 角色页发起新 Run R2，继承当前书籍但不继承“总纲已完成”的假设 → R2 读状态发现方向生成中，可做讨论建议，但依赖正式总纲的角色生成等待/提示 → J1 完成事件通知 → 作者确认总纲后 R2 才可采用相关设计。初期同书写互斥由后端统一执行。

### E.4 点击“写第二章”但第一章尚未审阅入库

command chapter.write → 依赖检查返回 previous_memory_pending → 不调用写作模型 → 展示第一章审阅入口及阻塞原因 → 作者确认入库 → W8 完成 → 重新验证第二章章纲是否过期 → 必要时重新确认 → W6 写作。若第一章内容已改，旧 reviewed_hash 无效。

### E.5 “把第三章的误会改成双方都知道真相”

读取第三章及之前证据 → 独立读取第四章之后做影响分析 → 提出新章纲与受影响章节列表 → 作者确认修改范围 → W6/W7 生成第三章候选 → 作者采用 → 保存版本，第三章及后文相关记忆 pending → 原第四章正文保留 → 作者逐章保留/修订并复核 → 新索引就绪。后文可读入影响分析，但不能作为第三章人物已知事实。

### E.6 “按方案连续写三章，最多 100 积分”

形成 scope=本书下一连续三章、预算上限、有效期、草稿采用/入库策略 → 作者确认计划 → W10 每章顺序推进。若用户未允许自动章纲采用，则每章计划等待；若允许仅对本计划自动采用，也不能覆盖其他章。每步预留预算，预估不足就提前停。第二章发现规则矛盾则 partial，返回第一章成果和停止原因；不能为凑三章降低审核门槛。

### E.7 写章途中作者关闭网页、刷新再回来

后端 J1 已领取 → SSE 断开但任务仍执行 → 新页面按 run_id 拉快照、after_seq 补事件 → 若 J1 已成功直接显示产物；若 waiting_author 展示原确认卡；若 outcome_unknown 明确显示核验状态。不会重新提交生成，也不会把整段流式文本重复追加。

### E.8 向量服务余额不足

W8 已保存正文审阅版本 → embedding 返回 429/1113 → 任务 failed/quota_exhausted、Run partial 或 failed → 正文和失败回执保留、loaded 不更新 → 不自动继续下一章。额度恢复后用户显式重试索引，建立关联的新 attempt，旧回执不删除；已确认正文未变化时可复用审阅授权，不强迫重新审阅同一稿。
