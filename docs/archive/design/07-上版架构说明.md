# StoryClaw 运行架构

> 历史归档：保留当时方案或验证结果，不代表当前实现。现行说明从[阅读导航](../../00-阅读导航.md)开始；文中旧命令不应直接照做。

当前实现采用 Harness/App 分层，目录规则参考 [DeerFlow 官方说明](https://github.com/bytedance/deer-flow/blob/main/backend/AGENTS.md)。

作者端 React 与独立运营端 React 通过 `/api/v1` 访问同一个 FastAPI Gateway。Gateway处理鉴权、参数和HTTP协议；应用服务处理SQL、作者确认、任务、积分、对象存储和发布。后台 Worker 持久化推进任务，切换页面不会结束任务。

AI核心是独立可安装的 `backend/packages/harness`，公开 `import storyclaw`。`StoryClaw` 门面提供命令入口和有界自然语言主循环；专业 LangGraph 与 Workflow 完成选题、规划、写章、改稿和审阅。Skill仅提供写作方法，不拥有业务权限。主循环、Workflow与Skill各有职责，不叠加无限自主循环。

依赖方向为 `app → storyclaw`，Harness通过明确的Ports与注入回调访问应用能力，禁止反向导入应用、FastAPI和SQLAlchemy；自动架构测试约束边界。后端不得直接调用模型 `ainvoke/astream` 或导入 LangChain/LangGraph。

PostgreSQL是用户、作品、版本、任务、确认和账务的事实源。Milvus与Neo4j是按用户/作品/来源/索引代次隔离的衍生检索层；作者审阅、版本匹配、提取完整后才激活。正文变更使依赖失效，旧索引不能静默成为新事实。MinIO承担Milvus依赖和平台私有原稿对象存储。

Docker分别运行API与Worker，但二者安装同一个AI包。没有独立LangGraph HTTP服务器、Redis/Celery或本地免登录产品版本。`app.main:app`保留为部署入口；真正装配位于 `app.gateway.app`。热更新挂载和安装路径均使用新Harness目录。
