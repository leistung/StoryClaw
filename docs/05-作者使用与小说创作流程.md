# 05 作者使用与小说创作流程

## 从零开一本书

1. 注册登录，在首页与选题伙伴讨论，或直接新建作品。先确定题材、主角、核心冲突与创作方向。
2. 首页采用分组问题，正常选题先集中收集信息再给方案；作者要求修改方案可以继续讨论，不应无限反复问同样的问题。
3. 作者检查开书窗口中的书名、简介、题材、主角、单章字数和创作目标，人工确认后才创建作品。
4. 在工作台生成或手写总纲，整理故事方向与近期阶段，保存并确认。
5. 补充当前需要的世界规则、角色和重要设定。手动整理可以逐步进行；AI依赖操作会检查前置条件。

**连载规划不是预先锁定全书章节。** 总纲描述方向与阶段；每章临写前单独确定章纲。目标字数/章数是规划参考，不是产品保证一次写完的数量。

## 第一章参考什么

第一章没有上一章正文。它主要参考：开书资料、已确认总纲、世界/角色/情节设定、当前章纲、可选场景任务单、私人写作方法。若为来源接管或分支，还包括作者确认的基线与允许资料范围。

在创作页新建第一章，生成或手写本章章纲，检查并确认；可选生成场景任务单。再发起写章任务，完成后阅读正文、修改和保存。

连载模式会检查章纲是否确认、是否依赖当前版本；仅有书名或一段模糊简介不能替代确认总纲。

## 第二章和后续章节参考什么

先审阅上一章当前正文，再发起故事记忆入库。正文写入SQL不等于已经进入有效知识索引。

下一章使用当前有效总纲/设定、当前章纲、最近上一章正文、允许历史的向量与图检索、有效摘要和事实等。上一章正文有长度上限；远期历史通过检索和结构化记忆取用，不是把全书每次塞进提示词。

若前文有正文但记忆未完成或已失效，系统会阻止依赖操作并要求处理。无正文的未来空章节不等于待入库历史。

基本节奏是：**规划当前章 → 作者确认 → 写正文 → 审阅修改 → 确认当前版本入库 → 下一章**。

## 润色、续写与改稿

局部润色、段内续写、对白和场景增强通常产生候选，作者决定是否采用。整章生成/修订可能通过带版本校验的后台任务写入正文；已有内容覆盖需要相应确认，保留旧版本。

改早期章节或重要设定后，后文章纲依赖、知识索引和影响提示可能失效。系统提示复核，不会擅自重写后面所有章节。应按故事顺序审阅受影响部分，必要时改章纲、改正文、重新审阅入库。

生成期间作者手动编辑的新版正文不能被迟到的旧任务无声覆盖。版本冲突时查看候选与历史，不要连续重复点击生成。

## 连续计划

创作管理中创建有限章节范围和积分预算。默认在章纲确认、正文审阅等节点等待作者；只有明确授权自动采用的有限计划才会自动推进。当前单个计划最多101章，不能等价理解为无限全自动连载。

暂停会阻止新调用，已经发出的供应商请求可能完成。失败先看任务错误、候选和费用，再决定显式恢复。

## 已写一半的旧稿

上传自有TXT/DOCX，先核对拆章结果、缺章/重章提示和来源权限；按允许范围分析来源，确认截止位置、已有剧情状态和继续创作的基线。

旧稿接管应在符合条件的作品中进行，不能仅上传文件后立刻声称百万字历史全部理解完成。来源分析/索引有持久任务，未完成的基线与完整就绪基线处理不同；历史改稿也可能使基线失效。

## 基于原作写分支

在独立作品中复用同账号可访问的来源，确认续篇、IF、AU或原创角色分支规则、截止位置和改写内容。原作与新作品命名空间独立，截止之后的内容不应冒充已发生事实。

软件中的权限确认和商业用途字段不构成实际版权授权；没有外部版权核验服务。原作权利未确认时不能把分支自动当成可商业投稿作品。

## 发布

先核对当前稿与来源状态、未处理影响和平台规则，创建冻结投稿包。本平台可对明确批准的快照安排站内发布；外部平台目前采用导出ZIP、人工投稿、人工登记回执。后续改稿不会偷偷替换已批准的旧快照。
