# Agent 重构实施与验收记录

日期：2026-10-25。对应 [统一设计](STORYCLAW-AGENT-DESIGN.md)。设计目标、已实现代码和实际验证分别记录。

## 现在的入口

作者端工作台新增 **创作管理**：旧稿与分支、连续计划、发布准备、私人方法和叙事记忆。普通大纲/角色/章纲/正文/记忆入口保留；右侧助手使用统一 StoryClaw 门面。运营端仍独立运行。

| 工作流 | 已实现入口与执行 | 作者需要做什么 |
| --- | --- | --- |
| W1 选题开书 | 首页既有分组选择/讨论/编辑开书卡 | 确认开书资料，不自动创建 |
| W2 总方向 | 大纲页、framework.draft | 保存并确认；连载不锁定全部章数 |
| W3 创作档案 | 角色/世界观/情节页、setting.draft | 选择采用候选；可随创作继续补充 |
| W4 当前章纲 | 创作页、chapter.plan | 当前章单独规划和确认 |
| W5 场景任务单 | 当前章场景按钮、chapter.scenes | 可选；依赖变化失效 |
| W6 正文/修订 | chapter.write / chapter.revise，后台 WorkJob | 已有正文聊天覆盖需确认，保留历史 |
| W7 局部编辑 | 润色/续写/场景/对白候选；助手候选采用按钮 | 审阅采用；版本不符拒绝覆盖 |
| W8 审阅入库 | 故事记忆、knowledge.ingest | 确认 reviewed_hash；向量/图/摘要完整后激活 |
| W9 改稿影响 | 保存/恢复旧版本/修改设定后失效提示 | 核对本章和后文；不自动改后续正文 |
| W10 连续推进 | 创作管理→连续计划 | 给定章范围/积分预算/自动采用授权；默认确认处暂停 |
| W11 旧稿接管 | TXT/DOCX 上传、拆章预览、来源分析、基线确认 | 自有旧稿在空白作品接管，确认截止位置及近期状态 |
| W12 原作分支 | 来源列表复用同账号资料，独立作品确认 derivative | 选择续篇/IF/AU/原创角色、截止章和覆写规则 |
| W13 投稿准备 | 冻结正文版本、ZIP 导出、回执登记 | 核对平台规则并手动提交；回执明确为作者填报 |

这里“已实现入口”不表示主设计中每一项远期扩展都已完成，尤其不代表真实模型的文学质量已验收。

## 架构与方法

- `StoryClaw` 支持 command、chat、stream、status、events、resume、cancel。有界主循环通过能力目录调用代码 Workflow；按钮复用提交策略。
- AI 推理、提示词、创作方法、切片/向量/图操作位于 `packages/storyclaw`；后端负责权限、SQL、任务、积分、文件和作者决定。
- 11 个方法包（8核心+3按需）有版本/内容哈希；旧名称有 alias；排队期间方法变化会停止。旧执行流程不再伪装成 Skill。旧资料归档于 `docs/archive/skills-v1`。
- 私人方法最多20份、同时启用5份；仅当写作资料，不执行代码；变化进入章纲/正文依赖指纹。
- 助手 `author.ask` 可返回最多3个问题的选项卡，支持自填，填写后由作者发送；不能代替覆盖/发布确认。

## 长篇资料与知识

- 单文件24MB，TXT支持UTF-8/UTF-16/GB18030；DOCX有解压规模限制。最多6000章，单章最多10万字符；没有标题则分块并警告。保留原始文件、哈希、内部稳定顺序和来源标题；缺章/重复提示供人工核对。
- Docker 已启用 MinIO/S3 私有原稿存储；SQL 保存对象指针、大小及哈希。上传和迁移都要写后读回校验，确认后才释放 SQL 二进制副本。未部署S3的测试环境仍可使用数据库适配器。同账号文件复用和分支权限由服务器校验；不是公共原作库。
- 来源按6000字符段分析，逐段保留摘要、事实引用、信念持有者/确定程度、未解问题。证据引用必须能在对应原文找到。
- 原作单独 `source_<uuid>` 命名空间，编辑作品单独 book 命名空间。来源向量/图使用 SourceIndex，正文使用 IndexManifest。失败暂存不进入有效检索。
- 接管 baseline 分 assisted_ready / baseline_ready；未完整处理时不允许自动连续采用。作者修改已接管历史会使基线失效，并移除该章原文豁免，不能继续引用旧稿冒充新稿。
- 当前章参考：确认总纲/规则、当前章纲、上章正文、允许范围内检索、有效版本摘要/事实、作者基线与分支规则。检索截止章在查询前过滤；来源后续不作为已发生事实。
- 新索引使用独立物理ID，SQL激活时检查正文哈希及向量/图就绪。Neo4j实体按章节代次隔离，避免暂存新描述污染旧版本。
- 章节指纹由 PostgreSQL 写入触发器更新；旧章一次补建。规划读取轻量历史元数据，不把百万字历史正文全拉进 Python；上章才读取正文。历史依赖现在使用增量前缀哈希链：追加只计算尾部，修改/删除第N章使N起的缓存后缀失效；索引代次也参与依赖，入库只影响后续，不重置当前章已确认计划。它是可恢复的增量链，不宣称实现通用Merkle DAG。
- 摘要/事实存有效 manifest，带正文哈希/章节来源；检索有大小限制。角色信念不当作客观真相。新增人物标准名/别名映射、候选/确认/排除、知情人物、公开常识、信念持有者、故事时间、有效章段和显式因果边。别名冲突、跨书原因、未来原因和因果环会被拒绝。每章可选择人物视角；结构化参考按当时知情范围过滤，原文检索仍需要叙事审阅，不承诺模型绝不泄露角色未知信息。

## 持久任务与费用

- Run/Event、WorkJob、StudioTask 持久化。切换页面不重发；请求编号校验相同参数。后台独立消费者，等待任务不让模型轮询。
- 连续计划每次最多101章，不预建后续全部情节；预算约束每次文本/embedding调用。默认在章纲确认和正文审阅处等待作者；只有显式授权的有限计划才自动采用。
- 暂停/取消阻止新的调用；正在发生的调用可能完成并保存当前步骤，不能承诺供应商中断。进程结果未知不自动重复收费调用，必须核对后显式恢复。
- 模型/embedding调用前预留，按供应商可获得的 token 用量结算，避免旧汇总重复扣分。未获供应商用量时释放用户预留并标 unknown；这不是声称上游没有成本。超上限记 needs_reconciliation，不能无声透支。
- 旧聊天/生成兼容接口也接入计量上下文。主 Agent 的统筹调用也通过同一 ModelCall 预留/结算，保留本轮100积分上限及事件。首页选题也接入；格式失败按原政策补偿退款，保留供应商用量，禁止通过对账重新补扣已退款格式失败调用。
- 运营端「日志与审计→模型用量与待对账」已支持供应商回执登记、原计价快照复算、幂等对账和可选余额调整；默认只登记上游用量，不补扣用户。补扣仍受余额及作者预算约束，记录审计。尚未接通供应商自动账单回调。Docker 已拆独立 storyclaw-worker，API 不轮询队列；消费者退出会让 Worker 健康检查失败，SQL租约继续保护未知结果不自动重试。

## 发布和数据边界

- ReleaseRecord 冻结所选正文版本/内容哈希/目标平台/作者规则核对；后续改稿不影响旧投稿包。
- 本站（平台名 storyclaw）支持作者明确批准固定快照、未来时区时间预约公开、取消和真实投递状态。投递与成功标记同事务，后续改稿不替换已批准快照；转私密会取消待执行预约。外部平台依旧是ZIP+人工提交+作者回执，没有外站官方连接器和自动签约/作者分账。
- 来源商业用途未确认、基线失效或章节有未处理改稿影响时，拒绝商业投稿准备。
- 删除作品检查运行任务和跨分支来源引用；按依赖顺序删除本项目数据，不删除被其他分支使用的来源。已增加SQL清理outbox：删除对象/章节/作品和退役索引在保留24小时后执行；每次物理删除前复核有效引用，失败退避重试，运营可检查后显式重试。成功清理有cleaned标记，避免旧记录占满发现队列。

## 验证记录

- 隔离 PostgreSQL 测试库运行 **74项后端回归通过**，覆盖原接口、统一门面、跨用户隔离、幂等/确认/取消、方法版本、来源/基线/撤销、预算、manifest激活、候选采用和共享来源删除保护。
- 12章、超过2.5万字的确定性模拟模型流程：逐章规划→确认→写入→审阅索引→推进→完成。它验证程序编排，不是生成文学样书的验收。
- 超过500万字、1800章的合成文本拆章测试通过；不是500万字真实模型生成/全量模型阅读基准。
- 前端4项测试、TypeScript检查及生产构建通过。工作台编辑器依赖已拆包，构建大小见当前产物。浏览器自动化连接超时，交互视觉未自动验收。
- 容器只读烟测通过：11方法、旧别名、Run状态和事件续读，以及来源/基线/计划/投稿/私人方法接口；0次模型调用、0处小说正文修改。
- 原有第四章索引任务没有自动重试；没有清库或发布用户内容。当前新做的小样已成功调用glm-5.1和真实向量接口，消耗2平台积分，说明当前配置可用，不代表旧任务自动恢复。

可重复脚本：[refactor_acceptance.py](../novel-lab/refactor_acceptance.py)、[architecture_smoke.py](../novel-lab/architecture_smoke.py)。新增迁移 `0012_studio`、`0013_operations` 新增状态表及章节指纹/前缀失效触发器，生产按迁移流程部署；开发 create_all 不替代历史迁移。
