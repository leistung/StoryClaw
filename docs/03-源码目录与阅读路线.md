# 03 源码目录与阅读路线

本文按 2026-10-26 整理后的源码核对；当前目录是事实，项目现状见[01](01-项目概览与实现现状.md)，远期差距见[13](13-已知限制与后续路线.md)。

## 建议的源码阅读顺序

1. 从`frontend/src/App.tsx`看页面入口，再看工作台和任务组件如何调用API。
2. 读`backend/app/main.py`、`gateway/app.py`，理解启动、路由和依赖注入。
3. 选`gateway/routers/agent.py`或`jobs.py`，跟到services与Ports适配。
4. 读`storyclaw/agents/lead_agent/agent.py`，再看能力目录、Graph和Workflow。
5. 对照models、索引清单、计量和集成测试，理解如何保存、确认和恢复。

文件表用于查找，不要求从头读完。基础原理见[04](04-系统架构与运行原理.md)和[06](06-Agent工作流与Skill原理.md)。

## 运行和依赖方向

作者端/中台 → HTTP `/api/v1` → `app.gateway.routers` → 应用服务 → `StoryClaw` / 专业 Workflow。
AI 包通过注入端口回调应用服务，由服务执行鉴权、查库、任务调度和作者确认。**`app` 可以依赖 `storyclaw`，`storyclaw` 不得导入 `app`、FastAPI 或 SQLAlchemy。** 架构测试扫描实际目录，并断言目录存在及含有源码，避免迁移后空扫描。

`app.main:app` 继续作为稳定 ASGI 部署入口，仅转出 `app.gateway.app` 的 app/lifespan。API 路径、前端请求和数据表保持兼容。API 和 Worker 在各自进程中安装同一个 Harness；不是额外的 AI HTTP 服务。

`StoryClaw` 是公开门面：按钮 command 直接验证并调用能力；自然语言 chat 走有界 Agent Loop；专业工作流负责具体生成。Skill 是提示和参考材料，不拥有 SQL、扣费或发布权限。

## 应用服务分组

| 目录 | 职责 |
| --- | --- |
| services/agent | Run 生命周期、能力执行、工具适配和作者决定 |
| services/writing | 开书、章纲依赖、逐章规划、改稿、候选恢复与上下文数据 |
| services/writing/chat_workflow | context 组装输入，conversation 对话，chapters 写章/改章/流，history 历史/重试/反馈 |
| services/writing/writing_workflow | context 读写公共数据，editing 润色续写，batch 批量，analysis 分析，assistance 辅助创作，scenes 场景规划 |
| services/knowledge | 有效索引版本、历史指纹、叙事事实、Embedding 配置和故事记忆 |
| services/library | 自有旧稿与原作来源、基线和导入授权 |
| services/jobs | WorkJob 与连续推进任务；状态由 SQL 持久化 |
| services/platform | 配置、模型路由数据、积分、逐次用量、会员和账单核对 |
| services/storage | 私有文件、孤儿回收和作品依赖清理 |
| services/publishing | 冻结版本交付、站内定时发布与外部回执 |

同名目录中的 `__init__.py` 只负责公开导出；不存在第二份旧业务实现。下面逐文件列出实际用途。`__pycache__`、虚拟环境和构建产物不属于源码。

## 配置、方法、测试和实验为什么这样放

`backend/config`归平台应用所有，数据库平台配置仍优先于YAML初始值。`storyclaw/config`是AI包自身的环境配置代码，两者职责不同。内置方法归AI包所有，通过package-data进入wheel；不依赖仓库根目录或额外的`/app/skills`挂载，仍支持`SKILLS_DIR`覆盖。

测试归各自模块：Harness纯AI逻辑测试放包旁，平台测试放backend/tests，前端测试留在frontend/tests。真实生成需要预算和人工授权，放backend/evaluations，不混入自动回归。119份原实验输出迁入evaluations/runs，迁移前后SHA-256完全一致，且不进入Git和Docker构建上下文。专项样书恢复工具放backend/scripts/samples。历史实验文档归docs/archive/experiments。

## 本地开发与 Docker

```bash
.venv/bin/python -m pip install -e backend/packages/harness
make test                 # 离线AI、后端单元和作者端测试，无模型费用
docker compose --env-file .env -f deploy/docker-compose.yml up -d --build
```

Compose继续使用`storyclaw`项目名和原有持久卷；后端和Worker挂载backend及Harness代码以热更新。部署目录改名无需清库。当前编排仍为开发模式，正式生产部署需要另行配置。

详细测试说明见 [backend/tests/README.md](../backend/tests/README.md)，真实模型实验见 [backend/evaluations/README.md](../backend/evaluations/README.md)，部署说明见 [deploy/README.md](../deploy/README.md)。
