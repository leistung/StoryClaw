# 02 本地运行与配置

## 首次启动

需要Docker Engine及Compose；macOS本地通常通过Docker Desktop提供。从项目根目录执行：

```bash
# 只有尚未创建.env时才复制；已有环境不要覆盖
cp -n .env.example .env
docker compose --env-file .env -f deploy/docker-compose.yml up -d --build
```

| 地址 | 功能 |
| --- | --- |
| `http://localhost:5173` | 作者端 |
| `http://localhost:5174` | 运营中台 |
| `http://localhost:8010/docs` | 后端交互式API文档 |
| `http://localhost:8010/health` | API基础健康检查 |

端口以`.env`和`docker compose ps`为准。基础健康正常不代表模型、支付或所有知识库流程可用。

## 注册与管理员

在作者端`/register`注册，之后登录。新环境没有默认管理员和默认密码。

```bash
# 提升已经注册的用户；将示例名称替换为自己的用户名
docker compose --env-file .env -f deploy/docker-compose.yml exec backend python -m app.admin_cli 你的用户名
# 或交互创建一个全新的开发管理员，不在命令里写密码
docker compose --env-file .env -f deploy/docker-compose.yml exec backend python -m app.admin_cli admin --create
```

`--create`会给新管理员发放10000开发积分，不是供应商余额，也不应当用作公开注册送分方案。已有同名账号不会被覆盖密码。修改权限后重新登录中台。

先在中台配置文本模型、对应平台编号的积分价格和真实Embedding配置，再进行AI创作。只有页面能打开并不表示模型已准备好。

## 配置分别在哪里

| 位置 | 用途 |
| --- | --- |
| `.env` | 本机密码、连接、端口及环境开关，不提交Git |
| `.env.example` | 可提交的开发样例，含开发占位值，不能作为生产密钥 |
| `backend/config/*.yaml` | 新环境的模型、定价、会员初始值 |
| PostgreSQL `platform_configs` | 中台保存的实际平台配置，优先于YAML |
| AI包 `skills/resources` | 内置写作方法，随包安装；可用`SKILLS_DIR`覆盖 |

`.env.example`仍含早期LangGraph Server变量；当前Compose没有独立LangGraph服务，这些旧字段不是启动依赖。实际设置项以[应用配置](../backend/app/config.py)和[Compose](../deploy/docker-compose.yml)为准。

## 修改端口

```dotenv
BACKEND_HOST_PORT=8010
FRONTEND_HOST_PORT=5173
ADMIN_HOST_PORT=5174
ADMIN_PUBLIC_URL=http://localhost:5174
WRITER_PUBLIC_URL=http://localhost:5173
```

宿主机8010映射至后端容器8000。Docker内两个前端仍通过`backend:8000`代理，因此只改宿主机后端端口无需改Docker内API地址。前端端口或域名变化时，同步检查`CORS_ORIGINS`和两个公开跳转URL。

直接在本机启动作者端时，在`frontend`内使用`VITE_PROXY_TARGET=http://localhost:8010 npm run dev`；本地中台同理。前端开发代理与浏览器实际访问地址是两件事。

## 热更新与日常命令

当前两个前端使用Vite开发服务器；API使用Uvicorn reload，Worker监听Python变化。热更新会重启部分进程，生成中的调用可能中断，不应在真实付费长任务期间随意改代码。方法资源变化仍由方法指纹和任务校验保护，不能承诺所有进程对所有文件都同时热重载。

```bash
make up-all
make health
make logs
make down
```

源码改变通常可热更新；依赖或Dockerfile变化需要重建；环境或Compose变化需重新创建相应容器。数据库结构变化另走迁移。`make down`不删除持久卷，不要为排错随意增加`-v`。
