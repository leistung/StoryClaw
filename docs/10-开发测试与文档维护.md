# 10 开发、测试与文档维护

## 开发入口

两个前端分别安装自己的依赖。Python开发使用独立环境，安装`backend/requirements.txt`及可编辑AI包`backend/packages/harness`。完整服务开发优先用Compose，以免误把容器地址当成本机地址。

源码归属见[03](03-源码目录与阅读路线.md)。新增功能应先确定属于平台数据/授权，还是AI策略/推理；不要为了快速调用把LangChain逻辑写进API。

## 默认测试不调用模型

```bash
make test                  # AI包、后端单元、作者端文本测试
make test-backend          # Python离线部分
make test-frontend         # 作者端4项现有测试
```

默认离线Python部分66项：35项Harness、31项平台单元。完整Python回归共96项，还包含28项隔离数据库集成与2项端到端。

管理端目前没有独立测试用例，不能把构建成功说成全量交互已验收。两个前端可分别执行`npx tsc --noEmit`及`npm run build`，作者端另有`npm test`。

## 完整集成回归

只允许数据库名`storyclaw_refactor_test`，需要事先建立一次性数据库；脚本拒绝生产库名。命令中使用环境变量，不在文档写真实密码。

```bash
DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST:PORT/storyclaw_refactor_test   make test-integration
```

入口`backend/scripts/test.py`支持`--suite offline|integration|all`和`--pattern`。测试会在隔离库写测试数据，模型使用模拟，不自动连接生产数据库或开始真实生成。

## 测试放在哪里

| 路径 | 目的 |
| --- | --- |
| Harness的tests | 主循环、上下文、方法、模型适配等纯AI逻辑 |
| backend/tests/unit | 数据契约、参数和边界逻辑 |
| backend/tests/integration | 数据库、权限、计费、Run与来源状态 |
| backend/tests/e2e | 完整API/滚动创作；另有显式实际服务冒烟脚本 |
| frontend/tests | 目前的正文格式测试 |
| backend/evaluations | 真实模型/质量实验，不进入默认测试 |

实际服务的`architecture_smoke.py`会登录并提交无模型的状态Run以检查队列，不是完全不写任何记录，但不改小说正文、不调用模型。真实生成、样书修复和model-check需显式运行，不能加入CI默认目标。

## 文档怎样维护

主手册按00—13编号。一项知识只在一个主章节详细解释，其他地方链接过去；README只保留入口和最短启动方式。历史方案和实验放archive并注明时间，不能不断往现行说明末尾追加过时结论。

每次功能变更同步更新对应章节：用户行为改05，Agent改06，检索改07，账务改08，模型改09，运行/部署改02或11，限制改13。目录/文件移动更新03与本地链接；API字段以OpenAPI为准，不维护另一份容易过期的手写接口大全。

```bash
make docs-check            # 当前手册与入口文档的链接、编号及忽略规则检查
```

文档检查不重新运行付费模型，也不扫描历史归档中的旧命令是否仍可执行。现行文档的代码路径必须可定位；测试结果要注明范围与日期，不把合成文本或模拟模型测试写成真实文学作品验收。

## Git忽略规则

提交源码、测试、迁移、方法资源、配置样例和文档。忽略本机环境、所有真实.env变体、密钥、缓存、构建产物、运行报告与样书输出。`.env.example`及明确的`.env.*.example`保留。

`.gitignore`只影响未跟踪文件；已经提交过的敏感文件不会自动从历史消失，需要单独审查处理。本次检查不自动删除或重写Git历史，也不修改既有用户数据。
