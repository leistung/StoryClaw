# 09 模型配置与故障处理

## 配置优先级

平台文本模型和价格先看数据库平台配置，再看`backend/config/models.yaml`和`pricing.yaml`初始值。修改YAML不一定覆盖中台已保存的配置。

用户选择的是平台模型编号；配置中的`model`才是供应商模型名。两者可以不同，但积分价格必须对应平台编号。密钥由后端加密保存，浏览器模型列表不返回密钥。

新环境需要管理员自行配置。没有默认供应商账户，不应把曾经验证过的开发密钥或密码写进文档。

## 当前测试模型顺序

初始测试目录为`glm-4.5-air → glm-5.3-flash`，地址为`https://open.bigmodel.cn/api/paas/v4`，使用OpenAI Chat Completion兼容格式。实际启用情况以中台/数据库为准。

额度降级仅在HTTP429且明确错误码`1113`或`insufficient_quota`时发生；最多切换一次。普通限流、鉴权错误、参数错误、超时、预算不足或作者取消不会自动切换。

流一旦产生任何chunk，不再切换模型，避免混流或重复执行工具。每次调用独立预留、结算；备用模型同样受预算保护。测试费率是平台积分规则，不是供应商人民币报价，也不代表免费调用。

GLM-5.3-Flash适配强制启用思考并使用temperature=1。思考消耗输出预算，较小max_tokens可能只留下很短正文；连通性通过不代表章稿完成。

## Embedding单独配置

Embedding是把切片转成向量，不是正文生成模型。中台设置模型、地址、密钥和输出维度；输出必须与Milvus索引配置一致。

旧实验使用过Embedding-3，不代表新环境已经配置。开发中的hash/内存回退只能用于限定测试，不能把它当作真实语义检索或持久知识库验收。更换Embedding模型或维度需要评估重建索引，不能只换模型名沿用旧向量。

## 常见故障

| 表现 | 首先核对 |
| --- | --- |
| 模型不可用/无价格 | 平台编号、enabled、对应价格、密钥、格式和上游名 |
| 401/403 | 上游密钥或权限；不要将密钥回显到日志 |
| 429/1113 | 上游额度不足；平台积分和上游余额分开检查 |
| 普通429 | 并发或限流；核对后显式重试，不无限自动重试 |
| 400/1210 | 参数与模型契约，例如Flash思考设置 |
| 格式异常 | 查看完整性/截断与候选，不绕过JSON校验创建作品 |
| 索引失败/维度不符 | Embedding真实维度、Milvus连接、上游额度、当前正文版本 |
| API健康但AI不可用 | 启动注入警告、模型配置、数据库与知识存储；不能只看/health |

## 显式运维命令

```bash
# 查看活动任务，不调用模型
docker compose --env-file .env -f deploy/docker-compose.yml exec -T backend python -m app.ops_cli activity
# 已配置GLM密钥后，显式切到两款测试模型；会修改实际平台配置
docker compose --env-file .env -f deploy/docker-compose.yml exec -T backend python -m app.ops_cli configure-test-models
```

`model-check`是实际付费探测，每次最多5个平台积分，包含文本和向量请求；普通测试不会执行它。原始实测记录见[归档](archive/records/05-模型切换原始记录.md)。
