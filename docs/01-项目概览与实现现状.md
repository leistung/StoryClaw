# 01 项目概览与实现现状

核对日期：2026-10-26。

StoryClaw是面向作者的AI小说创作平台。目标是让作者与AI共同确定故事方向、逐章创作、维护上下文，再准备发布。当前定位是**已有较完整创作流程的开发版本，尚未完成商业上线验收**。

## 三个代码主体

| 主体 | 技术与职责 |
| --- | --- |
| 作者端 `frontend` | React、Vite；作品、工作台、任务、社区、消息、会员申请和帮助 |
| 运营端 `admin-frontend` | 独立React应用；模型、定价、会员、用户数据、日志、用量与维护操作 |
| 后端 `backend` | FastAPI平台应用，加独立可安装的LangChain/LangGraph AI包 |

作者端和中台共用后端，分别登录。不存在免登录的本地产品版本；不会自动创建默认管理员或默认密码。

## 已实现的主要业务

| 业务 | 当前实现 | 不能据此推断 |
| --- | --- | --- |
| 创作 | 选题讨论、人工开书确认、总纲/阶段、设定、逐章章纲、场景、写章、改稿和版本 | 不保证AI自动生成可签约作品 |
| 知识 | 正文审阅、版本化索引、向量/图检索、摘要/事实、角色知情与别名规则 | 不保证模型完全没有矛盾或视角泄漏 |
| 长篇 | 有限预算连续计划、自有旧稿接管、来源分支和近期状态基线 | 不代表百万字真实生成与并发规模已经验收 |
| 任务 | 持久Run、WorkJob、StudioTask、事件、确认、暂停、取消和候选恢复 | 无法保证取消已发生的供应商调用 |
| 社区/发布 | 社区互动、本站明确批准后的冻结快照发布、外部投稿包和人工回执 | 外站自动发布、签约与作者分账未实现 |
| 商业基础 | 注册登录、管理员、模型配置、积分预留/结算、会员申请与人工处理 | 在线支付、退款及自动财务闭环未完成 |

当前Compose包含**9个服务**：作者端、中台、API、Worker、PostgreSQL、Milvus、Neo4j、etcd、MinIO。AI通过外部模型接口推理，仓库没有部署GPU推理服务。

## 最近一次验证及其范围

2026-10-26目录整理时，96项Python测试通过：35项AI包、31项后端单元、28项隔离数据库集成、2项端到端。另有4项作者端文本格式测试通过。实际服务检查验证了11份方法、别名、事件及Worker领取，未调用模型、未改正文。

AI包wheel安装到独立临时目录后，从项目以外的工作目录仍可加载11份方法；44份资源字节一致。119份既有实验输出迁移前后哈希一致。

历史真实模型探测验证过`glm-4.5-air`与`glm-5.3-flash`连通，但Flash小预算正文短，不能作为完整章节质量验收。旧样书存在因上游额度不足暂停的任务及保留候选，没有自动恢复。长文本拆章和12章模拟写作测试验证的是代码编排，不是百万字文学作品质量。

## 项目现在最需要补齐什么

生产部署、迁移基线、备份恢复与告警、真实支付、内容运营闭环，以及有人工评审的持续长篇评估。详细差距见[13](13-已知限制与后续路线.md)。
