# 12 接口与数据模型导航

本章提供找代码的路线，不复制一份完整接口schema。接口参数、枚举和返回字段以运行中的 `http://localhost:8010/docs` 与Pydantic定义为准。业务API统一挂在 `/api/v1`，基础健康接口独立。

## 前端入口

| 作者端路由 | 页面职责 |
| --- | --- |
| `/login`、`/register` | 账号登录与注册 |
| `/` | 首页选题与作品入口 |
| `/workspace/:bookId` | 作品工作台、设定、章纲、正文、记忆和创作管理 |
| `/jobs` | 持久任务与结果 |
| `/community`、`/post/:id` | 社区与作品交流 |
| `/read/:bookId`、`/share/:token` | 阅读及分享入口，仍按实际授权校验 |
| `/messages`、`/recharge`、`/help` | 消息、会员申请及使用指南 |
| `/admin`、`/llm-configs` | 旧入口跳转独立中台 |

路由由[App.tsx](../frontend/src/App.tsx)定义。中台有自己的React入口和Token，管理请求仍由后端检验管理员身份。

## AI能力目录

下面按当前能力注册源码列出，不表示每个能力都直接修改正文。能力的schema、持久任务类型和覆盖确认属性由[capabilities.py](../backend/packages/harness/storyclaw/orchestration/capabilities.py)定义。

| 能力 | 当前说明 |
| --- | --- |
| `author.ask` | 一次集中询问最多3个必要问题，提供可点击选项并允许自填；不代替创作确认 |
| `project.status` | 查看当前作品的真实章纲、正文和记忆状态 |
| `character.knowledge` | 查看当前章开始前的人物知情、信念、证据与被隐去的秘密数量 |
| `library.status` | 查看本作品只读来源、接管基线和覆盖程度 |
| `library.search` | 查询作者确认截止范围内的原作和接管证据 |
| `plans.status` | 查看本作品连续计划、暂停原因及预算 |
| `release.status` | 查看本作品冻结投稿包与人工回执，不代替外站发布 |
| `material.read` | 读取当前章节和本书确认规划，不读取其他书 |
| `memory.search` | 检索本书允许历史的有效正文证据 |
| `framework.draft` | 生成总方向/阶段草案，等待作者确认 |
| `setting.draft` | 生成世界观/角色/情节草案，等待作者采用 |
| `chapter.plan` | 生成当前章纲草案，等待作者确认 |
| `chapter.scenes` | 生成确认章纲的可选场景任务单 |
| `chapter.revise` | 按作者要求修改当前章，已有正文先请求确认并保留旧版本 |
| `chapter.write` | 生成并保存当前章；已有正文需作者确认覆盖 |
| `idea.brainstorm` | 根据当前书籍约束生成多个创意候选，不改正文 |
| `title.suggest` | 生成当前书籍或章节标题候选，不自动改名 |
| `text.polish` | 润色作者指定的本章片段，返回候选不覆盖正文 |
| `text.continue` | 基于当前章结尾续写短片段，返回候选不覆盖正文 |
| `text.scene_enhance` | 增强本章指定场景片段的表达，保留事实 |
| `text.dialogue_polish` | 打磨本章指定对白片段，保留信息 |
| `book.analyze` | 生成指定范围的分析/摘要报告，不修改正文 |
| `knowledge.ingest` | 对作者确认的正文版本建立知识索引 |

## SQL数据模型

SQLAlchemy模型是业务结构的事实来源；建表/升级另见Alembic。正文、计划、确认、索引清单的关系不仅由外键决定，还由服务层版本和权限规则约束。

- User → Book → Chapter 是作品归属主线；章节版本单独留存。
- 总纲、设定与章纲依赖是规划资料；部分工作流数据放在ConfigEntity/JSON字段，不能仅看表名推断用途。
- Run、事件、决定、Job、连续计划保存执行与授权状态。
- ModelCall/积分流水/用量回执保存成本与核对记录。
- 来源、基线、原稿对象与索引代次共同决定检索范围。
- ReleaseRecord冻结具体内容，ReleaseDelivery保存站内交付；人工回执不等于外站已由系统投递。
