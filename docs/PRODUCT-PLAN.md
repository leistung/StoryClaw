# StoryClaw 产品与实现

本轮沿用深色鼠尾草绿界面，完善面向创作者和平台运营者的核心流程。保留 React、FastAPI、LangChain/LangGraph、PostgreSQL、Milvus 与 Neo4j。

## 创作流程

1. 注册登录，创建作品，填写故事简介、世界观与人物，维护分卷和章节大纲。
2. 在章节工具栏生成场景任务单；任务单持久化，并作为本章写作上下文。
3. 发起章节写作，在任务中心查看排队、运行、完成或失败。关掉页面不取消后台任务；排队任务可以取消。
4. 审阅正文，手动修改或使用现有润色工具。版本历史支持预览和恢复；恢复前自动保存当前版本。
5. 将确认的章节更新到故事记忆，供后续章节检索。正文改动后记忆标记为待更新。
6. 在作品信息页明确发布，生成公开阅读快照。编辑草稿不会同步修改已发布内容；更新发布或取消发布由作者操作。

## 数据职责

PostgreSQL 保存用户、小说正文、设定、大纲、版本、任务、发布快照、社区、会员和流水等业务事实。Milvus 保存检索向量；Neo4j 保存抽取的实体关系。后两者是可重建的辅助记忆，不能代替正文。当前图片沿用现有资源方式，尚未增加对象存储上传生命周期。

新增表在 `0009_product.py` 中，不清空原有业务数据。测试使用独立 PostgreSQL 测试库。

## 一致性与计费

同一章节的活跃任务阻止正文写入；直接 AI 调用在提交时再次校验正文摘要，避免迟到结果覆盖新稿。正文写入、积分扣减和流水在同一事务中提交。任务请求使用 request_id 去重，付费任务失败不会自动重试。

任务消费者目前运行在 API 进程中，使用数据库持久化和租约。进程退出或租约过期后记录失败，避免自动重复付费；开发热更新期间请等待任务完成再改后端。多实例通过数据库锁领取任务，但尚未部署独立 worker 服务。

会员目前是人工审核开通：用户提交申请，管理员核对后批准或拒绝，批准只发放一次权益及积分。旧模拟购买入口已关闭。页面标明不会在线扣款；尚未接通微信或支付宝、支付回调、退款和自动对账。积分按平台接口结算，不能视为供应商全部内部模型调用的精确账单。

## 验证与后续

后端集成测试覆盖跨用户权限、发布快照隔离、版本恢复、AI 并发保存冲突、扣费失败回滚、任务幂等及失败状态、社区审核和会员重复审批。前端包含正文转换测试，并执行类型检查和生产构建。

2026-10-23 验证：后端 16 项测试通过，前端 4 项测试通过，用户端和独立中台均通过类型检查和生产构建。真实 GLM 流程在《借火人间》第 8 章生成了 4 个场景任务、保存 1,807 字正文、完成 4 个记忆片段和 11 条实体记录入库。正文低于 2,800 字目标，任务结果保留需修订提示；执行完成与文学质量达标分别展示。未对真实作品执行公开发布或会员权益发放，相关权限及事务在隔离测试库验证。

正式商业上线仍需真实支付接入、对象存储及备份、独立任务 worker 和容量测试、监控告警、内容审核策略、会员退款流程。故事一致性检索与 AI 审阅辅助创作，不能保证长篇小说完全没有逻辑矛盾。本轮没有宣称已生成或验收完整十万字小说。

## 选题讨论与首次创作引导

首页选题伙伴使用 `/assist/ideation` 讨论，分为 discuss 和 proposal 两种模式。讨论不会建书；提案需要用户采用，再进入可编辑创建表单，最终仍通过原有创建接口确认开书。书名、简介、类型、主角、章节数与每章目标均经过结构校验，总字数按章节数乘以每章目标计算。人工创建入口继续保留。

讨论成功结果与积分流水原子保存，以用户及 request_id 去重；相同请求编号但不同内容被拒绝。页面显示讨论积分消耗，失败可重试同一请求。当前标签页会话缓存讨论；不是跨设备同步的长期选题档案。后端成功结果保留以支持请求重试，不会自动创建书籍或自动生成正文。

作品右侧创作路线按资料、大纲、真实章节、场景任务、正文、人工审阅、记忆入库提示下一步。点击步骤仅导航到相应功能，生成仍需用户主动操作。路线收起状态与人工审阅标记按用户和作品保存在当前浏览器；人工审阅标记不构成服务端质量审核，改稿后需要重新核对。场景完成提示依据当前返回的任务记录。

侧边栏默认使用紧凑间距，提供独立展开/收起按钮，桌面收起后保留图标导航；短窗口仍保留滚动作为兜底。测试覆盖提案格式、未确认不建书、鉴权、重复请求不重复扣费与请求编号冲突。

### 选题对话的流式交互

参考 assistant-ui 的 Thread 交互（https://www.assistant-ui.com/docs/primitives/thread），首页使用固定高度聊天框，消息区独立滚动，输入区固定在框内底部。发送立即显示用户消息与思考状态；仅当阅读位置接近底部时跟随新增文本，上翻历史暂停跟随。回复保留空行、单独展示编号问题，安全渲染为文本，不执行模型 HTML。

`/assist/ideation/stream` 使用真正的上游模型流，SSE 推送 reply 字段的增量；提案仍需完整结构校验。只有完成校验并提交事务后才推送 done；失败显示错误，不能把部分文本当作已保存结果。断线可用相同 request_id 重试，已提交结果直接返回，不重复扣费。解析测试包含中文、换行、转义符与 emoji 被拆分到多个 chunk 的情况。

### 对话中的可点击问题

选题回复可带 `questions` 数组，每轮最多两题，每题有 2–5 个选项及单选/多选标记。流式正文完成并确认保存后，底部面板显示问题；用户可以选择建议、补充文字，点击确认后把问题和所选答案作为下一条用户消息发送。关闭只收起面板，仍可在对话中重新打开。自由输入和最终开书人工确认继续保留，旧的历史回复没有问题字段时按普通对话显示。
